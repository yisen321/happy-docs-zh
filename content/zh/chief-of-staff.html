参谋长#

参谋长是启动 Happy Desktop 后获得的第一个机器人，也负责设置 Happy。告诉它你的需求：添加模型账户和提供商、导入首个项目、配对手机、部署服务器；它只会就必须由你决定的选项和登录操作询问你。

要设置 Happy，只需告诉参谋长：

  • 示例

    帮我开始使用 Happy

  • 示例

    添加我的工作 Claude 账户，并在它与个人账户之间轮换

  • 示例

    将 Codex 设为新会话的默认选择

  • 示例

    配对我的手机

  • 示例

    在我的服务器 ubuntu@203.0.113.10 上安装 Happy Agent

  • 示例

    创建一个名为 Release Notes 的机器人，负责起草每周发行说明

首次打开 Happy Desktop 时会发生什么#

  1. 至少登录一项模型订阅：Claude、Codex 或 Grok。Happy Agent 启动前需要至少一个提供商。
  2. 配对手机，或跳过此步骤。
  3. Happy Desktop 打开参谋长，消息框中预填草稿：“帮我开始使用 Happy。我们选一个项目或新建一个项目，然后一起完成一项小改动。查找本地项目或更改任何内容前先询问我。”只有你点击发送后，这条消息才会发出。

发送后，参谋长最多会推荐三个你近期在 Claude Code 或 Codex 中使用的文件夹。它只读取路径，绝不读取对话。你可以选择其中一个、指定其他文件夹，或新建项目，然后与它商定第一项小改动。

每个安装的 Happy Agent 首次启动时都会创建参谋长，因此你部署的服务器也会有一个。

设置模型与提供商#

完成初始设置后，参谋长会通过编辑 happy.toml 更改模型设置：

  • 为提供商添加另一个账户：通过 claude setup-token 添加 Claude 账户，在独立的 CODEX_HOME 下登录 Codex 账户，提供 Grok 身份验证文件，或为 Bedrock 配置 AWS profile。
  • 汇集同一提供商的多个账户，让新会话在账户之间轮换，遇到配额或登录错误时转到下一个账户。参见同一提供商的多个账户。
  • 在模型选择器中隐藏账户或限制模型，包括可供子智能体使用的模型。
  • 设置新会话的默认值：提供商、模型、推理力度和服务层级。
  • 将现有会话转移到其他提供商。

它会在编辑前备份文件，绝不打印、复制或发送凭据。文件位于工作区之外，因此 Auto 模式下的编辑需要经过审查。

你可以让它做什么#

操作配方重现了 Happy Agent 源码中的参谋长指令。

向它提出的请求会发生什么
设置我的第一个项目推荐近期使用的 Claude Code 和 Codex 文件夹（仅路径），导入你选中的文件夹或新建项目，并商定第一项小改动
添加账户、更改模型按上文所述，编辑 happy.toml 中的账户、账户池和默认设置
配对手机或修复手机访问执行手机访问流程，复用现有配对，不重置 ~/.happy 即可诊断问题
在我的服务器上安装智能体在你通过 SSH 访问的机器上将 Happy Agent 安装为服务，使用你批准的提供商凭据和 Git 身份，并连接到你的 Happy Desktop
创建团队登录 Happy Social、创建团队、以团队模式部署、验证连接，最后发送邮件邀请
创建机器人创建持久机器人，具有自己的名称、文件夹和一段持续的对话
对外开放这台机器开启或关闭 Tailcat；因为会让机器可从互联网访问，Auto 模式下需经过审查
升级 Happy Agent检查发布版本、平滑关闭、私密备份、替换二进制文件、验证

它会复用你已经做出的选择，不会把设置变成一份问卷。遇到浏览器、设备登录、SSH 和钥匙串审批时会暂停，完成后继续。

只有参谋长能做的事#

参谋长是管理员机器人。其他机器人不能创建机器人、管理与其他 Happy Agent 的连接、创建或管理 Happy 团队、为整个安装添加技能文件夹，或开启/关闭 Tailcat。

参谋长不会做的事#

  • 它与任何会话一样，遵循相同的权限模式和沙箱规则。审查被拒绝就是最终决定。
  • 打开初始设置不代表同意。你发送请求之前，它不会检查任何内容。
  • 发现项目时仅读取文件夹路径，绝不导入对话文本或凭据。
  • 它绝不删除或重置 ~/.happy，也不会移动你未指明账户的凭据。
  • 除非你提出要求，否则它不会提交、推送、发布、部署或发行版本。
