模型与订阅#

Happy 使用你已经付费的订阅来运行 Claude、Codex 和 Grok。在机器上登录 Claude Code、Codex 或 Grok CLI 后，Happy 就会使用相应凭据：无需购买 Happy 模型访问套餐，也无需粘贴密钥。Gemini 通过 Google 的 Antigravity 使用你的 Google 登录运行；OpenCode 或任何 Agent Client Protocol（ACP）智能体使用其自身的登录方式运行（测试版）；参见运行框架。

要添加账号，只需告诉参谋长：

  • 示例

    添加我的工作 Codex 账号，并在它与个人账号之间轮换

可用模型在整台机器范围内统一，因为目录由守护进程管理。请求携带你的凭据直接发送到厂商；Happy 绝不代理这些请求。

在会话中途切换模型#

你随时可以从应用或手机修改会话的模型或推理强度。对话记录会保留。各提供商的不透明数据（推理内容、响应条目）按原样保存，并原封不动地交还，因此切换不会破坏历史记录。新模型会使用其所属厂商的提示词和工具；权限模式、沙箱及工作区不会改变。

在一个任务中使用多个模型#

每个子智能体分别选择自己的模型和推理强度，不继承任何设置。同一个任务可以用一家提供商做规划，另一家做实现，再用第三家做审查。参见永不消亡的智能体。

上下文压缩如何工作#

Happy 决定何时压缩；提供商使用其原生压缩能力或自己的压缩提示词，决定如何压缩。结果会作为一条可见消息出现在对话记录中，并指出它替代了哪些内容。

使用同一提供商的多个账号#

在 happy.toml 中以命名提供商的形式添加账号。

[providers.work_codex]
type = "codex"
enabled = true
auth_file = "/Users/me/.codex-work/auth.json"

命名实例会作为独立提供商显示在选择器中。要在同类型账号之间自动轮换，可将它们放入一个智能提供商的账号池中，并隐藏成员。

[providers.codex]
hidden = true

[providers.work_codex]
type = "codex"
enabled = true
hidden = true
auth_file = "/Users/me/.codex-work/auth.json"

[providers.codex_pool]
type = "smart"
strategy = "round_robin"
providers = ["codex", "work_codex"]
enabled = true

新的智能体或子智能体会随机选取一个成员开始，并持续使用它；发生认证错误或配额耗尽错误时，会切换到下一个成员。hidden = true 仅将账号从选择器中隐藏，账号池仍会将请求路由给它。参见配置。

提供商用量与配额#

提供商配额大约每十五分钟轮询一次，并显示在应用中。这些是观测数据，不是计费记录。
