通过 WorkOS 登录团队#

Happy Agent 团队服务器由 WorkOS 提供支持。WorkOS 负责每位成员的登录并维护团队成员关系；服务器只在每次请求时检查签名令牌，绝不会接触密码。更想使用自己的身份提供商？可以改用它。

WorkOS 负责什么#

  • 账号与登录：AuthKit。你的 Happy Social 账号是一个 WorkOS 用户。Desktop 通过浏览器中的 AuthKit，使用公共客户端 PKCE 流程登录，因此应用不内置客户端密钥。轮换刷新的令牌始终留在你的机器上。
  • 团队：组织。Happy 团队是一个 WorkOS 组织，其中注册了服务器地址。创建团队后，你就成为其管理员。
  • 邀请。成员通过邮件加入。WorkOS 发送邀请并处理接受邀请的流程；邀请授予的是普通成员身份。
  • 每个团队独立的令牌。对于你连接的每个团队，Desktop 内的 Happy Agent 都会通过 WorkOS 的组织切换机制，用刷新令牌换取限定于该组织的访问令牌，并在每次请求时携带它。

服务器检查什么#

团队服务器要求每个请求（包括健康检查）都携带持有者令牌，不接受其他方式。只有用于告知应用如何登录的 GET /v0/authentication 是公开的。对于每个令牌，服务器都会在本地检查：

  • 使用 WorkOS 为 Happy 客户端发布的签名密钥验证 RS256 签名；这些密钥获取一次后会缓存；
  • 签发者和 client_id，以及 exp、iat、sub、sid 和 org_id 是否存在；
  • org_id 是否为该团队所属的组织。

不符合要求的请求一律返回 401。sub 中的 WorkOS 用户在首次保存个人资料时成为团队成员；被指定为所有者的用户会获得所有者权限。除了获取公钥之外，服务器在接受请求时不再调用 WorkOS。

[feature.team]
enabled = true
workos_client_id = "client_01KZD3XE9YAFAMT0P8TD4HP73E"
workos_organization_id = "org_..."
owner_workos_user_id = "user_..."

为什么选择 WorkOS#

账号、组织、邀请和会话，是团队产品中没人愿意重复构建的部分。交由 WorkOS 处理后，我们无需自行运营密码数据库或邀请邮件服务，而你自行托管的服务器只需检查签名，就能信任团队登录。感谢 WorkOS。

使用你自己的身份提供商#

设置 authentication = "jwt" 后，成员就会改用组织自己的 OAuth 2.0 服务器登录，例如 Okta、Entra ID、Google Workspace 或 Keycloak。应用直接与该服务器执行带 PKCE 的授权码流程。团队服务器只验证收到的 JWT 访问令牌；绝不会接收登录授权码或刷新令牌。此时登录不再涉及 WorkOS 账号。设置企业 JWT 登录介绍了具体步骤。

参谋长如何建立团队#

参谋长按照公开操作指南创建并部署 Happy 团队执行：确认账号、名称和端点，创建团队，配置团队模式，验证连接，最后发送邀请。
