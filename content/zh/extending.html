技能与 MCP#

扩展 Happy 中每个智能体的知识与能力：技能是在任务匹配时由模型加载的指令，MCP 服务器则提供来自其他进程或服务的工具。两者对 Claude、Codex 和 Grok 的工作方式都一样。

要添加技能，只需告诉参谋长：

  • 示例

    将 ~/team-skills 添加为所有智能体的技能文件夹

扩展方式增加的能力编写形式
技能模型按需加载的指令一个 SKILL.md 文件
MCP 服务器来自外部进程或 HTTP 服务的工具一条 mcp.toml 配置

只要提出要求，Happy 中的智能体就能编写这两种扩展。

技能：按需加载的指令#

---
name: release-notes
description: Use when asked to draft release notes from merged pull requests.
---

# Release notes

1. Collect merged PRs since the last tag.
2. Group them by area.

系统会从 ~/.agents/skills，以及从项目根目录到当前工作目录沿途的 .agents/skills 中发现技能；项目技能会覆盖同名的用户技能。技能名称和描述会加入系统提示词；任务匹配时，模型会读取完整文件。前置元数据中请求钩子、Shell 执行或权限变更的内容会被忽略。参谋长可以为整个安装实例添加更多技能文件夹；此后，每个智能体都会加载这些文件夹的子文件夹中的技能。

MCP 服务器：来自其他进程的工具#

mcp.toml 位于 ~/Happy/Config（macOS）、~/happy/config（Linux）或工作区根目录：

[mcp_servers.docs]
command = "docs-mcp-server"
args = ["--stdio"]

[mcp_servers.remote_docs]
url = "https://mcp.example.com/mcp"
bearer_token_env_var = "MCP_BEARER_TOKEN"

本地进程使用 Stdio，远程服务使用 Streamable HTTP。所有模型共享同一工具目录。MCP 工具需要 Auto 或 Full access 权限，且 Auto 模式下的每次调用都会接受审查。Codex 或 Claude Code 配置中列出的服务器不会被导入。
