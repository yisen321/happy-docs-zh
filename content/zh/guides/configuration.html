配置#

Happy 会读取两种可选的 TOML 文件：一份机器级配置，以及每个仓库各自的一份配置。它们设置默认权限模式、网络允许列表、受保护路径、工作区初始化、提供商和 Docker。

要修改配置，只需告诉参谋长：

  • 示例

    允许沙箱中的命令访问 api.github.com 和 registry.npmjs.org

文件位置#

作用范围文件
机器~/Happy/Config/happy.toml（macOS）、~/happy/config/happy.toml（Linux）
仓库仓库根目录下的 happy.toml

机器配置文件在首次启动时生成并带有注释，之后不会被覆盖。全局 AGENTS.md 与它位于同一目录。仓库配置在允许覆盖的地方优先；提供商、Docker 以及任何会对外开放机器的设置只能在机器级配置中指定。智能体对仓库配置文件只有只读权限。

MCP 服务器配置放在这两个位置各自的 mcp.toml 中。参见技能与 MCP。

默认权限模式#

[defaults]
permission_mode = "workspace_write"   # read_only | workspace_write | auto | full_access

沙箱命令的网络允许列表#

沙箱命令不能访问网络，除非目标列在这里。智能体不能自行添加域名；参谋长只有在你要求时才会编辑此文件，在 Auto 模式下该编辑会经过审查。

[network]
allowed_domains = ["api.github.com", "*.npmjs.org", "npmjs.org"]
allowed_ports = [443]
denied_domains = ["uploads.example.com"]

*. 不包含根域名。只读模式忽略此设置并保持离线；完全访问模式也忽略此设置，但不受网络限制。

受保护路径#

没有完全访问权限时，这些路径始终只读，即使位于工作区内也一样。机器级与仓库级列表会合并。

[permissions]
protected_paths = ["master-plans", ".env.production"]

工作区初始化命令与同步文件#

[workspace]
setup_commands = ["pnpm install --frozen-lockfile", "pnpm build"]
sync = [".env"]
protected_sync = [".env.production"]

初始化命令被视为可信项目代码，以完全访问权限运行。命令失败会被记录，但工作区仍可使用。

提供商与账户#

[providers.grok]
enabled = false

[providers.work_codex]
type = "codex"
enabled = true
auth_file = "/Users/me/.codex-work/auth.json"
include_models = ["openai/gpt-5.6-sol"]

存在凭据时，内置提供商会启用。include_models 和 exclude_models 用于精简选择器。hidden = true 仅影响显示：它会让账户无法被直接选择，但智能提供商（type = "smart"、strategy = "round_robin"）仍可将请求路由给它。参见同一提供商的多个账户。

Docker 会话#

[docker]
image = "my-project-dev:local"
workdir = "/workspace"
mounts = [{ source = ".", target = "/workspace" }]

容器内使用同一套权限模型。Happy 会将自己的沙箱挂载到容器中，无需安装额外软件包。Happy 不会自行拉取镜像。

happy.toml 中的其他设置#

生成的 happy.toml 通过内联说明记录其余设置：在线状态、Tailcat、团队模式、提供商传输方式、Bedrock、终端主题、崩溃诊断及功能开关。
