永不终止的智能体#

Happy 中的每段对话都是持久会话，关闭窗口或重启后依然保留。已完成的子智能体并没有消失；给它发送后续消息，它就会带着完整上下文恢复工作。你不在时提出的问题，会一直等到你回来。

要设置提醒，只需告诉参谋长：

  • 示例

    明天上午 9 点提醒我审查 acme/api 中尚未关闭的拉取请求

什么是会话#

会话包含工作目录、模型、推理力度、权限模式和对话记录。它存在于运行时中，而不是窗口中。每个会话都有一个无法猜测的智能体 ID；智能体通过它联系彼此。没有可供浏览的智能体目录。

子智能体：将工作委派给其他模型#

智能体将边界明确的工作委派给子智能体，默认在后台运行。嵌套深度最多三层；一棵树最多包含五个子智能体，已完成的也计算在内。

  • 每个子智能体独立选择模型和推理力度，不继承任何设置。
  • 子智能体启动时仅获得自己的任务。
  • 无论父智能体采用什么模式，子智能体都在 Auto 模式下运行。
  • 已完成的子智能体接受后续任务，而不是重新创建。
  • 后台子智能体完成后会通知父智能体，即使父智能体处于空闲状态。父智能体应继续工作或结束当前轮次，不必等待或轮询。

智能体如何互相发送消息#

消息可发送给智能体的创建者及其自身的协作者。对于其他对象（子任务、其他项目或其他机器），智能体必须使用获知的准确 ID 发送；未知 ID 会被拒绝。接收者会知道消息由谁发送。

持久等待与定时消息#

每个智能体都可以持久地等待一段时间，或等到最远一天后的指定时刻；期间重启不影响等待，新消息会提前结束等待。主会话可以向任何已知 ID 的智能体（包括自己）安排定时消息，提前数小时或数天设置。智能体可以列出和取消自己安排的消息。

收件箱与在线状态#

智能体提出的问题会显示在对话中；开启实验性功能后，同一问题也会显示在收件箱（Inbox）中，两处共享一个状态。在任意设备的任一位置作答，两边的问题都会关闭。

在线状态智能体的行为
在线问题可以无限期等待。
离开绝不因等待你而阻塞。自行决策，继续工作，在收件箱留下说明。

你可以在配置中定义自定义状态，指定等待时限和指令。运行期间发生的在线状态变化，会以通知形式传达给智能体。

Happy Desktop 为每个会话显示什么#

每个会话都会显示：执行阶段、运行中的工具、后台进程、子智能体、等待状态、整棵树的 token 用量、修改过的文件。你可以从应用连接智能体打开的终端。
