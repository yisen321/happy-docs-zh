设置或修复移动访问#

当有人希望通过手机上的 Happy Coder 控制 Happy Desktop，或远程控制终端中的 Claude Code/Codex 会话时，请使用本指南。移动访问是可选功能，账户主密钥保存在手机上。消息和会话内容在电脑与手机之间进行端到端加密。这并不是迁移到手机与 Agent 直接通信的传输方式。

统一的引导式设置#

使用 Desktop 初始引导中的移动访问流程，或进入设置 → 移动访问。这两个本地入口使用相同的引导式设置：选择启用；在 Desktop 准备旧版 Happy CLI 的同时，从 App Store 或 Google Play 获取 Happy Coder；确认应用已打开；在 Happy Coder 内扫描设备二维码并批准；等待终端设置完成。商店二维码用于下载应用，设备二维码用于授权电脑。设备授权只需扫描一次。

如果电脑已经关联，就复用现有关联并完成终端设置，不要要求再次扫码或强制登录。已保存的关联可能处于离线状态；在实时状态确认之前，不要称其已连接。CLI 与原生 Agent 仍有各自独立的机器注册信息。

要远程控制终端会话，请使用 happy claude 或 happy codex 启动。仅运行原版 claude 或 codex，不会让会话纳入 Happy 的远程控制。在对应电脑和守护进程在线时，手机也可以启动会话。

在不破坏现有设置的前提下诊断#

  • 绝不要删除、重置或递归修复 ~/.happy 或 HAPPY_HOME_DIR。Happy Agent 也使用该目录；现有历史记录、配置和账户状态必须保持完整。
  • 绝不要将 happy auth login --force 作为常规初始设置方法。账户/服务器不匹配时，需要用户决定使用哪个账户和服务器，而不是悄悄替换任意一方的登录信息。
  • Desktop 目前需要可用的 Node.js/npm 安装来准备终端 CLI。检查报告的前置条件、PATH 或权限错误。不要把使用 sudo 进行全局安装或递归更改所有权作为通用修复方法。
  • CLI 必须支持 happy auth desktop --check，其准确标记为 happy-desktop-link-v1。该标记表示本地命令能力，而不是 V1 账户认证；此交接支持 V2 凭据。如果已发布的 CLI 缺少此能力，应停止并说明需要兼容的构建版本。不要退回到交互式认证或强制认证。
  • 如果手机批准成功但终端设置失败，应保留原生配对并重试统一流程。happy auth desktop 会交接凭据并启动守护进程；它会修改状态，不是只读诊断。只有在用户授权的修复任务范围内才能运行。它直接返回的错误可以区分账户/服务器拒绝与守护进程启动/就绪失败。
  • 不要打印凭据文件、令牌、二维码载荷或私钥，也不要让用户粘贴这些内容。CLI 凭据位于共享主目录根部；原生凭据位于 agent/happy/ 之下。通过产品工具验证状态，不要通过复制密钥重建认证。
  • 就绪检查只在设置期间进行，不会持续进行。在当前实现中，CLI 守护进程因重启或崩溃而停止后，普通的 Desktop 启动不会自动将其重启。应说明这一限制，并使用已获授权的设置操作重新启动。不要将原生 Desktop 的连接状态与终端的启动/恢复就绪状态混为一谈。

远程 Agent 保留现有的仅面向 Agent 的移动访问流程。通过该 Agent 的设置进行连接；本地 Desktop 的终端自动关联不会在远程机器上安装 CLI，也不会向其传输凭据。如果任务涉及此情况，请阅读远程部署指南。

账户丢失、手机应用重装和已保存账户冲突，需要专门沟通恢复事宜。在用户选择保留哪个账户之前，保留双方状态。不要将发送通知或向老用户推广作为修复的一部分。

取消关联或切换手机账户#

当有人想让这台电脑从手机上移除、重新开始，或将电脑关联到另一个 Happy 账户时，使用此流程。为同一账户增加另一部手机不属于取消关联：应改为在新手机上恢复账户。

  • 取消关联（设置 → 移动访问 → 断开这台电脑，或 Happy 集成中的取消关联操作）会将这台电脑从 Happy 账户中移除。电脑及其发布的聊天会从手机上消失。本地历史仍保留在这台电脑上。同一账户的 Happy CLI 会话和终端 CLI 登录不会受影响。取消关联前，应确保用户理解聊天会从手机上移除；不要将取消关联作为常规排障操作。
  • 在手机上删除电脑（机器的删除操作）效果相同。Happy Agent 会检测到这一变化，或在下次启动时检测到，移动访问将恢复为尚未设置。要再次使用手机访问，请从这台电脑重新关联。
  • 如果取消关联时报告 Happy Agent 无法移除这台电脑，说明无法连接 Happy，且没有遗忘任何状态。电脑仍保持关联，但处于离线状态。检查连接后再次执行取消关联；流程会从停止处继续。如果用户更想保留关联，则重新启动移动访问以恢复连接。绝不要手动删除 access.key 或 machine.json，强行只在本地取消关联：这会让电脑继续留在手机上，却不再有可用于移除它的凭据。
  • 切换账户时，先取消关联，再选择连接手机，用登录目标账户的手机扫描二维码。这台电脑会作为新电脑加入该账户，并重新发布当前聊天及近期历史；旧账户将不再列出它。较旧的 Happy Agent 版本只会丢弃本地登录，而把电脑留在旧账户中。
  • 终端 CLI 保留自己的登录，可能对应另一个账户。通过移除已保存的终端登录单独管理；取消手机关联不会改变它。

完成检查#

确认预期账户保持不变、原生状态如实显示，并且终端守护进程设置已完成。取消关联后，移动访问应显示尚未设置；请用户确认电脑已从手机上消失。切换账户后，确认电脑出现在新账户的手机上。在具备真实设备和相应授权时，验证从手机启动和恢复 Claude/Codex。不要仅凭构建或单元测试结果就声称完成了真机检查。
