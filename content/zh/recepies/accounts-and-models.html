账号、模型、推理强度和服务层级#

当用户想添加提供商账号或将账号组成池、限制或更换模型、设置默认推理强度或服务层级，或把现有会话迁移到另一提供商时，使用本操作指南。如果要让 Claude Code、Codex CLI、Antigravity、OpenCode 或其他 ACP 智能体本身使用这些账号运行，请添加一个运行框架。这里的所有设置都是用户 happy.toml 中的机器配置。参考资料见配置。

编辑之前#

  1. 文件位于 ~/Happy/Config/happy.toml（macOS）或 ~/happy/config/happy.toml（Linux）。它不在工作区内，因此写入需要经过审查的完全访问权限。

  2. 读取时隐藏凭据：

    sed -E 's/^([[:space:]]*(oauth_token|api_key)[[:space:]]*=).*/\1 "<redacted>"/' ~/Happy/Config/happy.toml

  3. 备份文件：cp -p happy.toml happy.toml.bak-<timestamp>。

  4. 绝不要打印、复制或发送凭据，也绝不要在账号或机器之间复制凭据。

账号#

每个额外账号都是一个 [providers.<id>] 表，包含 type 和可选的友好名称 name。内置的 claude、codex 和 grok 默认显示为 Current CLI（当前 CLI）；其他未命名的账号则使用 ID 的可读形式。配置、默认值和账号池仍使用 ID。

用户明确指定的标签要原样使用。提出名称建议时，优先选择容易识别的邮箱式标签，例如 alex@example.com、alex@acme 或 alex.work@example.com。保留能区分账号的用户名和域名细节，避免过短的别名。省略多余的厂商或套餐前后缀：提供商分组已经提供了这些背景信息。这只是选择名称时的建议。产品会原样显示明确设置的名称，绝不会自动缩短邮箱或追加套餐名称。

厂商设置用户如何获取凭据
Claudetype = "claude"、oauth_token登录该账号后运行 claude setup-token；由用户将其粘贴到文件中。
Codextype = "codex"、auth_file使用独立的主目录登录，例如 CODEX_HOME=~/.codex-work codex login；指向其中的 auth.json。
Groktype = "grok"、auth_file该账号的 Grok 身份验证文件。
Bedrocktype = "bedrock"、profile、region该账号的 AWS 配置档案。
兼容 OpenAI 的服务type = "openai_compatible"、base_url、api_key_env、models从厂商获取 API 密钥，并导出到守护进程环境中。详见下文。

添加兼容 OpenAI 的厂商（OpenRouter、Together、Fireworks、DeepSeek、vLLM、LM Studio）只需一个表，并在 models 中填写厂商的精确模型 ID：

[providers.openrouter]
type = "openai_compatible"
name = "OpenRouter"
enabled = true
base_url = "https://openrouter.ai/api/v1"
api_key_env = "OPENROUTER_API_KEY"
models = ["deepseek/deepseek-v4.1-flash-1017"]
reasoning_field = "reasoning"

[providers.openrouter.request]
reasoning = { enabled = true }
  • 不要把密钥写入文件：将其放入 api_key_env 指定的变量，再从包含该变量的 shell 中重新加载守护进程。绝不要把密钥粘贴到 happy.toml、提交或消息中。
  • 只列出支持工具调用的聊天模型。先查看厂商的模型页面。在 OpenRouter 上，supported_parameters 必须包含 tools。
  • 上下文窗口、图像输入和推理强度会在后台从厂商的 /models 获取。可在 [providers.<id>.model_overrides."<model>"] 下覆盖其中任意设置。参考文档列出了全部设置。
  • 验证时，检查 GET /v0/config 是否在新提供商下列出这些模型，然后运行一轮使用工具的对话。

将同类型账号放到智能提供商后面组成账号池，并隐藏成员：

[providers.claude]
hidden = true

[providers.claude_work]
type = "claude"
enabled = true
hidden = true
oauth_token = "<from claude setup-token>"

[providers.claude_pool]
type = "smart"
strategy = "round_robin"
providers = ["claude", "claude_work"]
enabled = true
轮询行为
新智能体或子智能体随机选择一个成员开始运行。
后续轮次继续使用该成员。
身份验证或配额耗尽错误转移到下一个成员。
开始输出后失败不会在另一个账号上重放。
不支持权重、感知用量的路由或优先级路由、时间窗口，以及账号池的界面或 API。
设置效果
hidden = true不出现在模型选择器中；账号池仍可路由到它。
enabled = false完全停用，包括通过账号池进行的路由。
删除该表移除账号。
  • 已经使用隐藏提供商的会话会继续工作。如果需要它们轮换账号，请按照切换现有会话将其转到账号池；若 defaults.provider 指向隐藏账号，也要更新它。
  • 未被任何账号池列出的隐藏账号不会被使用。
  • 账号池只能组合相同类型的账号，Bedrock 账号还必须位于同一区域；其他成员会被静默跳过。

模型#

设置位置效果
include_models、exclude_models[providers.<id>]决定该账号在所有位置提供哪些模型，包括模型选择器。
include_subagent_models、exclude_subagent_models[providers.<id>]仅缩小新建子智能体时提供的模型范围。
provider、model[defaults]新会话的默认提供商 ID 和模型 ID。
  • 过滤器使用精确的 Happy Agent 模型 ID，例如 openai/gpt-5.6-sol。排除规则优先。
  • 账号池遵守成员的过滤规则：如果某模型只有部分成员提供，就只会路由到这些成员。
  • defaults.provider 可以指定账号池。

推理强度#

在 [defaults] 下设置 effort，例如 effort = "medium"。使用模型允许的级别；GET /v0/config 会按模型列出允许的级别。

服务层级#

位置设置
[defaults]service_tier = "default"、"fast" 或 "ultrafast"。
终端/fast 切换该会话的快速层级。
新建子智能体和工作区在创建工具上设置 service_tier: "priority"。
  • 只有所选账号和模型支持时，层级才会生效。GET /v0/config 会按提供商列出每个模型支持的层级。
  • 快速推理会消耗两倍的套餐用量。

切换现有会话#

  1. 通过 GET /v0/agents/:agentId/mode 读取上次提交的模式。
  2. 通过 PUT /v0/agents/:agentId/draft 提交该模式，仅更改 providerId，并保留用户已有的草稿文本。
  3. 该智能体的下一条消息会在新提供商上运行。

在同类型账号或账号池上保留相同模型属于兼容切换，会保留对话。不兼容的切换会创建全新的模型上下文，并附上一份交接说明。

应用并验证#

  1. 使用 TOML 解析器（例如 Python 3.11 的 tomllib）解析文件，并检查每个账号池成员是否存在。如果失败，修复文件或恢复备份。
  2. 按应用配置更改中的说明应用更改。
  3. 检查 GET /v0/config 或模型选择器是否显示账号池或新账号、是否不再显示隐藏成员，默认值能否正确解析，以及已切换的会话能否运行一轮。
