构建实时共享的 HTML 产物#

当一个 html 产物需要保存内容或供多人共享时，请使用本指南，例如待办清单、投票、报名表、记分板、小游戏，或供人批注的仪表盘。每个 HTML 产物都有自己的键值存储。守护进程通过页面自身源下的 /api/* 向页面提供存储服务，并将每项变更实时推送到所有已打开的页面副本。

准确的 HTTP 契约见已安装版本 API.md 中的“Artifact data”章节（在源码检出目录中为 packages/happy-agent/API.md）。本指南介绍浏览器 SDK，它封装了该契约，几乎所有页面都应优先选择它。

你将获得什么#

  • 每个产物独立的存储。同一产物的所有版本使用相同存储，因此通过修改文件发布新版本时，数据会保留。使用该 Happy Agent 的所有人共享这些数据：包括用户的每台设备，以及团队模式下的每位成员。
  • 知道谁在查看。happy.user 表示查看者：包含稳定的 id，以及 name、firstName、lastName 和 photoUrl，后几项都可能为 null。每次写入都会在 updatedBy 中记录作者，happy.users.load(ids) 可将这些 ID 转换为姓名和照片。身份始终来自已登录的人；页面不能冒充其他人。
  • 你也可以读写数据。read_artifact_data 展示产物数据及每个键的写入者，write_artifact_data 以你的身份设置或删除键。可以用它们汇报结果（“谁投了什么”）、填充初始数据，或修复错误值。你的写入会立即到达所有已打开的页面。其作者的 kind: "agent"，名称为你的机器人名称，或 "Agent"。
  • 可读取时间的版本号。每次写入都会获得一个 UUIDv7 version，它大于存储中所有更早的版本。happy.timeOf(version) 返回对应的 Date。
  • 实时变更。任何人的每项变更都会很快反映到所有被跟踪的值中。
  • 自动处理网络故障。写入会立即应用到页面，守护进程不可达时则进入队列。SDK 会采用退避策略重试，每次写入都携带幂等 ID，因此响应丢失后的重试绝不会重复应用。变更流会自行重新连接，并从上次看到的版本继续。
  • 自动向你报告问题。SDK 会将未捕获的错误、未处理的 Promise 拒绝、console.error、console.warn 以及自身同步问题发送到产物的调试日志；通过 read_artifact_logs，你可以查看谁在哪个版本遇到了这些问题。

容易出错的规则#

  1. 必须用 <script src="/api/v1/client.js"></script> 加载 SDK。它由守护进程提供，因此会随 Happy Agent 升级；绝不要将其复制到产物中。
  2. 始终使用绝对 URL /api/...。相对路径 api/... 会相对于页面自身路径解析，无法到达 API。
  3. 不要在产物的 api/ 目录下放置文件。显示页面的客户端会将 /api/* 发给守护进程，因此这些文件永远不会被提供。
  4. 其他所有资源都保存在产物内：不要使用 CDN 或其他网络资源。页面可能在无法访问互联网的环境中打开。
  5. 将存储视为共享且不可信的数据来源。任何页面副本，包括旧版本，都能写入任意键。验证读取的内容，使用 textContent 渲染文本，绝不用 innerHTML。
  6. 设计键时，应尽量避免多人写入同一键。为每个条目分配独立的键（todos/<id>），而不是使用一个大数组；可行时也为每个人分配独立键（votes/<userId>）。计数器等真正共享的内容应使用 happy.kv.update。
  7. 尚未确认的写入只保存在页面内存中，关闭页面就会丢失；守护进程的存储才是事实来源。
  8. 在页面开头加入 <link rel="stylesheet" href="/api/v1/style.css">，不要为 html 和 body 设置背景、外边距或内边距，让页面在浅色和深色模式下都能融入显示它的界面表层。内嵌应用会在回复中按完整高度绘制，因此不要设置固定高度，也不要设置内部滚动区域。保持扁平布局：不要在卡片内嵌套卡片，不要堆叠圆角卡片，也不要在卡片左侧添加彩色竖条。其余要求见 ../DESIGN.md 中的 Happy 设计系统。
  9. 按顺序编写页面：先 CSS，再 HTML，最后在 body 末尾放脚本，使其只在页面完整时运行。

标准样式与组件#

每个产物页面还可以加载由守护进程与 SDK 一同提供的另外两个文件，它们也会随 Happy Agent 升级：

  • 首先加载 /api/v1/style.css。即使不做其他设置，页面也会像应用的一部分：使用应用的字体和字号、浅色和深色配色、滚动条，并在透明页面上为文本、链接、代码、表格和分隔线提供基础样式。每条规则的优先级权重都为零，因此你自己的 CSS 总会优先；应有意覆盖，而不是习惯性覆盖。使用其变量代替固定颜色，它们会承载应用的取值：--happy-text、--happy-muted、--happy-faint、--happy-border、--happy-surface、--happy-accent、--happy-added、--happy-removed、--happy-diff-added、--happy-diff-removed，以及 --happy-chart-1 至 --happy-chart-6；字体相关变量为 --happy-font、--happy-mono、--happy-font-size 和 --happy-line-height；自行绘制滚动条时可使用 --happy-scrollbar-thumb、--happy-scrollbar-thumb-hover 和 --happy-scrollbar-size。
  • body 通过 --happy-page-inset 设置内缩：在聊天旁边或独立页面中，它对应应用的内容内缩；内嵌时则没有内缩，让页面与回复对齐。因此同一个页面可以适应全部三种场景；不要再自行添加外围外边距。
  • 最后加载 /api/v1/components.js。它定义了五个元素，从页面读取要显示的内容。在 Happy Desktop 中，差异和代码会使用应用自身的渲染器与样式绘制；在其他环境中则显示为不带高亮的普通编号行：
<!-- A unified diff, such as git diff writes, saved as a file of the artifact. -->
<happy-diff src="changes.diff"></happy-diff>
<!-- One file of it, and only lines 40–52 of the changed file. -->
<happy-diff src="changes.diff" path="src/app.ts" lines="40-52"></happy-diff>

<!-- Code from a file of the artifact: a header naming it, and only lines 40–52, numbered. -->
<happy-code src="src/app.ts" path="src/app.ts" lines="40-52"></happy-code>
<!-- A snippet written in the page; language names it, otherwise path or src does. -->
<happy-code language="python">
    <script type="text/plain">
        def greet(name):
            return f"Hello, {name}!"
    </script>
</happy-code>
<!-- Long lines wrap; nowrap on either element scrolls them instead. -->
<happy-code src="src/app.ts" nowrap></happy-code>

<!-- The files a diff changes as a tree, with status and counts; clicking one scrolls to its diff. -->
<happy-files src="changes.diff"></happy-files>
<happy-files>
    <script type="application/json">
        [{ "path": "src/app.ts", "status": "modified", "added": 12, "removed": 3 }]
    </script>
</happy-files>

<!-- "bar", "hbar", "line", or "area", drawn at the element's width; height="…" sets a plot's. -->
<happy-chart type="bar">
    <script type="application/json">
        {
            "labels": ["Mon", "Tue"],
            "series": [{ "name": "Requests", "values": [120, 340] }],
            "unit": "rpm"
        }

</happy-chart>

<!-- Mermaid flowcharts, sequence, state, class, and entity-relationship diagrams. -->
<happy-diagram>
    <script type="text/x-mermaid">
        flowchart LR

页面脚本也可以改为设置元素的 source 属性——差异文本、文件列表或差异文本、图表对象，或图示文本——元素就会重新绘制，因此实时应用可以用存储中的数据驱动图表。如果元素无法显示所提供的内容，会在原位说明原因。其他内容由你自行绘制：使用 --happy-* 配色的 SVG 可以自然融入。

SDK#

脚本一运行，window.happy 就已存在。

成员作用
happy.ready一个 Promise，在确定查看者身份且变更流首次连接后兑现。如果该 Happy Agent 没有数据 API，则会拒绝；旧版本不提供该 API。
happy.user查看者；在 ready 之前为 null。
happy.status、happy.onStatus(fn)可能为 "connecting"、"online"、"syncing"（已连接，有正在进行的写入或读取）、"offline"（正在重新连接），或 "unavailable"（产物已删除，或缺少 API）。onStatus 返回取消订阅函数。
happy.pending、happy.flush()尚未确认的写入数量，以及在所有写入均获确认后兑现的 Promise。
happy.timeOf(version)版本写入时的 Date。
happy.users.load(ids)、.get(id)、.cached(id)按用户 ID 获取并缓存人员信息。每人包含 id、kind（"user"，代理写入则为 "agent"）、name、firstName、lastName 和 photoUrl（可直接用作 <img src>）。未知 ID 会被略过。
happy.kv.trackPrefix(prefix)前缀下所有键的实时视图：entries（按键排序，仅包含当前有效的键）、get(key)、loaded、pending、synced、subscribe(fn)（立即调用，并在每次变更时调用；返回取消订阅函数），以及 stop()。
happy.kv.track(key)单个键的实时视图：exists、value、version、updatedBy、updatedAt、pending、loaded、synced、subscribe(fn)、set(value, options)、delete(options) 和 stop()。
happy.kv.set(key, value, options)写入 JSON 值。跟踪器会立即显示该值，并设置 pending: true。Promise 以确认后的条目兑现。选项：{ ifVersion } 仅在键仍为该版本时写入；{ ifAbsent: true } 仅在键没有值时写入。
happy.kv.delete(key, options)删除键，选项与写入相同。
happy.kv.update(key, change)执行读取、修改和比较后设置，发生冲突时最多重试 8 次。change(current) 接收当前值或 undefined，返回下一个值；返回 undefined 则删除键。
happy.kv.get(key)、.entry(key)、.list(prefix)一次性读取：分别获取本页面看到的值、确认后的条目或 null，以及前缀下所有确认后的条目。
happy.kv.onChange(fn)以条目形式接收本页面获知的、来自任何人的每项已确认变更。删除操作具有 deleted: true。
happy.debug.log(message, data, level)向产物调试日志添加一条来源为 app 的记录。data 是可选 JSON；level 为 "info"（默认）、"warn" 或 "error"。用它记录有人报告问题时你希望了解的事件。
happy.debug.disable()、happy.debug.flush()停止本页面的所有上报，或立即发送已排队的内容，而不是在两秒内发送。

条目的结构为 { key, value, deleted, version, updatedBy, updatedAt, writeId }。跟踪视图额外提供 exists 和 pending。在视图中，写入待确认期间的 updatedBy 是查看者的 ID。

被拒绝的写入会以携带 status 和 code 的 Error 拒绝其 Promise，跟踪器会丢弃乐观更新的值。当 ifVersion 或 ifAbsent 条件不成立时，code 为 "conflict"，此时 error.current 包含该键的当前状态。"too_large" 表示值超过 256 KiB，"storage_full" 表示存储超过 100,000 个键或 64 MiB。因网络而失败的写入绝不会被拒绝：它会等待并重试。

键长为 1–512 个字符，不能含控制字符。值可以是任意 JSON。已删除的键会保留记录 30 天，让重新上线的页面能够获知删除；离线更久的页面会重新读取存储，这由 SDK 自动完成。

完整示例：共享待办清单#

此页面列出所有人的待办事项，显示各作者的照片和姓名、同步状态，并支持离线使用。使用 create_artifact 将其创建为 html 产物，再通过 write_artifact_file 将其 index.html 原样写为：

<!doctype html>
<html lang="en">
    <head>
        <meta charset="utf-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <title>Shared to-dos</title>
        <script src="/api/v1/client.js"></script>
        <style>
            :root {
                color-scheme: light dark;
            }
            body {
                font:
                    15px/1.4 system-ui,
                    sans-serif;
                max-width: 34rem;
                margin: 2rem auto;
                padding: 0 1rem;
            }
            header {
                display: flex;
                justify-content: space-between;
                align-items: center;
            }
            #status {
                font-size: 12px;
                padding: 2px 8px;
                border-radius: 99px;
                background: color-mix(in srgb, currentColor 10%, transparent);
            }
            #status[data-status="online"] {
                background: color-mix(in srgb, green 20%, transparent);
            }
            #status[data-status="offline"],
            #status[data-status="unavailable"] {
                background: color-mix(in srgb, red 20%, transparent);
            }
            form {
                display: flex;
                gap: 8px;
                margin: 1rem 0;
            }
            input[type="text"] {
                flex: 1;
                padding: 6px 8px;
            }
            li {
                display: flex;
                align-items: center;
                gap: 8px;
                padding: 6px 0;
                list-style: none;
            }
            li.pending {
                opacity: 0.6;
            }
            li.done .title {
                text-decoration: line-through;
                opacity: 0.6;
            }
            .title {
                flex: 1;
            }
            .avatar {
                width: 22px;
                height: 22px;
                border-radius: 50%;
                object-fit: cover;
                background: color-mix(in srgb, currentColor 20%, transparent);
            }
            .meta {
                font-size: 12px;
                opacity: 0.7;
            }
            ul {
                padding: 0;
            }
        </style>
    </head>
    <body>
        <header>
            <h1>Shared to-dos</h1>
            <span id="status">Connecting…</span>
        </header>
        <form id="add">
            <input id="text" type="text" placeholder="Add a to-do" maxlength="200" required />
            <button>Add</button>
        </form>
        <ul id="list"></ul>
        <script>
            const statusLabels = {
                connecting: "Connecting…",
                online: "Synced",
                syncing: "Syncing…",
                offline: "Offline, changes are saved here",
                unavailable: "Unavailable",
            };
            const status = document.getElementById("status");
            function showStatus(value) {
                status.dataset.status = value;
                status.textContent = statusLabels[value] || value;
            }
            showStatus(happy.status);
            happy.onStatus(showStatus);

            const todos = happy.kv.trackPrefix("todos/");

            document.getElementById("add").addEventListener("submit", (event) => {
                event.preventDefault();
                const input = document.getElementById("text");
                const title = input.value.trim();
                if (title === "") return;
                // One key per item, so two people adding at once never conflict.
                happy.kv.set("todos/" + crypto.randomUUID(), {
                    title,
                    done: false,
                    by: happy.user && happy.user.id,
                    at: Date.now(),
                });
                input.value = "";
            });

            // Load each author once, and draw again when their names and photos arrive.
            const requested = new Set();
            function loadAuthors(ids) {
                const missing = ids.filter((id) => typeof id === "string" && !requested.has(id));
                if (missing.length === 0) return;
                missing.forEach((id) => requested.add(id));
                happy.users
                    .load(missing)
                    .then(render, () => missing.forEach((id) => requested.delete(id)));
            }

            function render() {
                const list = document.getElementById("list");
                list.replaceChildren();
                const entries = todos.entries
                    .filter((entry) => entry.value && typeof entry.value.title === "string")
                    .sort((a, b) => (a.value.at || 0) - (b.value.at || 0));
                loadAuthors(entries.map((entry) => entry.value.by));
                for (const entry of entries) {
                    const item = document.createElement("li");
                    item.className =
                        (entry.value.done ? "done " : "") + (entry.pending ? "pending" : "");

                    const box = document.createElement("input");
                    box.type = "checkbox";
                    box.checked = entry.value.done === true;
                    box.addEventListener("change", () => {
                        happy.kv.update(entry.key, (current) =>
                            current === undefined ? undefined : { ...current, done: box.checked },
                        );
                    });

                    const author = happy.users.cached(entry.value.by);
                    const avatar = document.createElement("img");
                    avatar.className = "avatar";
                    avatar.alt = "";
                    if (author && author.photoUrl) avatar.src = author.photoUrl;

                    const title = document.createElement("span");
                    title.className = "title";
                    title.textContent = entry.value.title;

                    const meta = document.createElement("span");
                    meta.className = "meta";
                    const when = entry.version ? happy.timeOf(entry.version) : null;
                    meta.textContent =
                        (author && author.firstName ? author.firstName : "Someone") +
                        (when
                            ? " · " +
                              when.toLocaleTimeString([], { hour: "2-digit", minute: "2-digit" })
                            : "");

                    const remove = document.createElement("button");
                    remove.textContent = "✕";
                    remove.title = "Delete";
                    remove.addEventListener("click", () => happy.kv.delete(entry.key));

                    item.append(box, avatar, title, meta, remove);
                    list.append(item);
                }
            }
            todos.subscribe(render);

            happy.ready.then(render, () => showStatus("unavailable"));
        </script>
    </body>
</html>

在两个窗口或两台设备上打开它，在其中一个添加待办事项，另一个会立即显示。关闭网络，添加并勾选条目，再恢复网络：它们会同步，而且不会重复。

其他模式#

  • 投票或回应：每位投票者使用一个键 votes/<happy.user.id>，值为其选项。跟踪 votes/ 前缀并统计。任何人都不会意外覆盖别人的投票。
  • 计数器或共享总数：happy.kv.update("score", (n) => (n || 0) + 1)。
  • 单个共享文档，例如看板布局：跟踪对应键，写入时使用 { ifVersion: tracker.version }。收到 "conflict" 拒绝时，显示 error.current，让用户合并或重试。
  • 在线状态（“谁在这里”）：页面可见时，每 30 秒向 presence/<userId> 写入 { at: Date.now() }，显示 updatedAt 较新的条目。在线状态键会不断积累，因此应在 pagehide 时删除自己的键。
  • 最近活动：使用 happy.kv.onChange 订阅，并展示 updatedBy 和 happy.timeOf(entry.version)。
  • 按创建时间排序：在键中使用 UUIDv7 风格或时间戳前缀，或按 happy.timeOf(entry.version) 排序；后者反映的是最近写入的时间。

不使用 SDK#

每个 SDK 调用本质上都是向页面自身源下的 /api/v1/... 发起普通 HTTP 请求，具体见 API.md：GET /api/v1/kv?prefix=，GET、PUT 和 DELETE /api/v1/kv/entry?key=，GET /api/v1/kv/changes?since=，以及来自 GET /api/v1/kv/events?since= 的服务器发送事件。为写入提供 writeId 以保证重试安全，使用 If-Match: "<version>" 或 If-None-Match: * 进行比较后设置；收到 reset 事件后，先重新读取存储，再从其新游标开始接收流。

直接处理数据#

  • 发布后为应用填充初始数据：使用 write_artifact_data，按页面脚本读取的键和值结构写入，例如键为 todos/<id>，值为 {"title":"…","done":false,"at":<ms>}。将 value 作为 JSON 文本传入。使用 ifAbsent: true，确保不会替换用户已经创建的内容。
  • 汇报数据：向 read_artifact_data 提供 prefix，即可列出键及其值、版本、作者和时间；通过 pageCursor 分页。
  • 修改其他人可能也在修改的值：先读取，再将 ifVersion 设为刚读取的版本进行写入。如果写入被拒绝，就重新读取后再决定；绝不能盲目重试。
  • 当数据结构必须改变时，优先修改页面。新旧版本共享一个存储，因此新版本仍须理解旧版本写入的数据。

调试应用#

上报自动进行。每个页面会将问题分批发送到 /api/v1/debug/log，每两秒一次，每分钟最多 60 条；浏览器离线或发送失败时，该批次会被丢弃而不是重试。SDK 自身的 sync 记录会说明变更流何时结束和重连、写入何时发生冲突或遭拒、页面何时必须重新读取数据，以及数据何时变为不可用。守护进程在数据旁为每个产物保留最近 7 天内最新的 1,000 条记录。

使用 happy-agent artifact dev 开发#

发布前，针对数据 API 的本地副本构建并测试应用：

happy-agent artifact dev ./my-app --scratch .context/my-app-data

它会在 http://127.0.0.1:4173/ 提供该文件夹，使用与守护进程相同的代码、限制和 SDK 响应 /api/*，并将数据和调试日志保存在 --scratch 文件夹中（不提供该参数时，使用退出即删除的临时文件夹）。它绝不会触碰守护进程的数据。通过普通 shell 命令或工作区终端启动，然后通过代理的工作区代理打开预览；该代理会从对应代理自己的机器发起每个连接。受限命令私有沙箱内的监听器与工作区代理相互隔离。

服务器的所有功能都位于 /__happy/ 下：/__happy/ 提供 HTML 面板，另有供脚本和你使用的 JSON 路由：

路由作用
/?as=Alice以虚构人物身份打开应用，包含姓名和自动生成的照片。每个标签页可以代表不同的人；不提供 as 时，页面身份为“You”。
GET /__happy/state显示文件夹、生效中的故障、打开的变更流，以及所有已知人物。
POST /__happy/faults可设置 { "offline": true }、{ "latencyMs": 800 }、{ "failNext": 3 }（返回 503，不应用写入），以及 { "dropNext": 1 }（应用写入后丢失响应）。
POST /__happy/streams/cut切断所有打开的变更流，模拟连接中断。
POST /__happy/data/write{ "as": "Bob", "key": "todos/1", "value": {…} }，或 "delete": true：模拟其他人的写入，实时传到每个页面。
POST /__happy/data/seed{ "values": { "key": value, … }, "as": "Bob" } 写入多个键。
GET / PUT /__happy/data导出所有条目，包括删除标记和作者；或使用此类导出内容替换数据。
POST /__happy/data/reset清除所有条目；已打开的页面会重新读取数据。
GET /__happy/logs、DELETE /__happy/logs按最新在前返回调试日志，支持 level、user（姓名）、limit 和 pageCursor；或清空日志。
GET /__happy/requests、DELETE最近 500 次数据请求，最新在前：请求者、状态、耗时以及应用的任何故障。

调试日志路由本身绝不会注入故障，因此日志能显示页面在中断期间上报的内容。以下循环可以发现大多数问题：

  1. 启动 artifact dev 并打开应用，再带上 ?as=Bob 打开一次。
  2. 以两个人的身份分别修改，然后制造网络问题：离线、增加延迟、使几次写入失败或丢失响应、切断流。检查两个页面最终显示的内容一致，而且 GET /__happy/data 包含预期数据，没有重复条目。
  3. 读取 GET /__happy/logs?level=warn 和 GET /__happy/requests，检查是否有异常。
  4. 通过一次 update_artifact 调用发布应用文件，每个文件使用 fromPath 形式，例如 { "fromPath": "my-app/index.html", "path": "index.html" }，使这次调用只生成一个新版本。为新产物调用 create_artifact 时也使用相同的 files。用户使用后，通过 read_artifact_logs 并按 level、userId 或 since 筛选，查看谁遇到了什么问题。

使用真实数据复现问题#

从已发布产物的数据副本启动服务器：

happy-agent artifact dev ./my-app --from <artifactId>

它会通过守护进程一次性读取产物的数据，包括版本和作者姓名，并且绝不写回。如果服务器无法连接守护进程，先保存副本，再从文件启动：

happy-agent artifact snapshot <artifactId> --out .context/my-app-data.json
happy-agent artifact dev my-app --seed .context/my-app-data.json --scratch .context/my-app-data

--seed 也接受由键和值组成的普通 JSON 对象。

使用浏览器驱动验证#

为了进行可重复的检查，可以使用 Playwright 和无头 Chromium 编写脚本，让真实浏览器访问开发服务器。不附带任何依赖：使用项目的包管理器在临时文件夹中安装 playwright-core（或 playwright），并使用电脑上已有的 Chromium（否则运行其 playwright install chromium 命令）。一个实用的脚本会：

  • 为每个人打开一个页面，使用 page.goto(base + "/?as=Alice")，并等待 window.happy.status === "online"；
  • 记录 page.on("console") 中的错误与警告、page.on("pageerror") 和 page.on("requestfailed")；
  • 执行一段场景，在步骤之间调用 POST /__happy/faults，并通过 page.waitForFunction 等待每个页面的文本趋于一致；
  • 最后保留截图、各页面可见文本、GET /__happy/data 和 GET /__happy/logs，以便判断每个人看到了什么，以及存储实际保存了什么。

注入故障期间出现请求失败和控制台错误是预期行为；其他异常都属于问题。

发布前检查#

  • 页面通过绝对路径加载 /api/v1/client.js，产物不在 api/ 下保存文件，也不从互联网加载任何内容。
  • 条目键按条目或按人划分，共享值使用 update 或 ifVersion。
  • 页面展示 happy.status 和待确认条目。
  • 对从存储读取的所有内容进行验证，并通过 textContent 渲染文本。
  • 已在 happy-agent artifact dev 中以两个人的身份运行，并验证离线和响应丢失场景；两个页面最终一致，没有重复条目，调试日志也没有意外内容。
