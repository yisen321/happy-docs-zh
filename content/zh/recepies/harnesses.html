执行框架：Claude Code、Codex CLI、Antigravity、OpenCode 与 ACP 智能体#

当用户希望 Happy 智能体使用其他厂商完整的智能体，而不是 Happy 自己的执行循环时，使用本操作指南：例如直接使用 Claude Code、Codex CLI、Google Antigravity、OpenCode，或任何提供 Agent Client Protocol 服务器的智能体。账号及其凭据仍在账号与模型中管理；执行框架仅决定由谁在这些账号上运行智能体循环。

用户体验会有哪些变化#

Happy 自己的执行框架使用 Happy 的提示词、工具和上下文压缩来运行循环。claude_code 执行框架在 claude 账号上直接运行 Claude Code：使用它自己的提示词、工具、设置、技能、子智能体及上下文压缩。codex_cli 则在 codex 账号上以同样方式运行 Codex。Antigravity、OpenCode 和其他 ACP 智能体自行登录，因此它们各自以独立账号的形式提供，名称与其执行框架相同。

无论哪种方式，对话始终属于 Happy。Happy 的历史记录是正式记录，智能体自己的会话会与之保持同步。Happy 的工具（项目、子智能体、产物、消息等）通过 MCP 提供给智能体，Happy 的权限模式也会映射到智能体自身的权限模式。智能体工作时发送消息可以引导它调整方向：Claude Code 和 Codex CLI 会在回合中途接收消息；Antigravity、OpenCode 和其他 ACP 智能体会被中断，然后从新消息继续。停止操作会结束智能体当前回合及其正在执行的命令。

执行框架运行内容使用账号机器上需要准备的内容
happyHappy 自己的循环所有提供商（默认）无需额外准备
claude_code通过 Agent SDK 运行 Claude Codeclaude 提供商（默认全部）无需额外准备；Happy 内置 Claude Code
codex_cli通过 codex app-server 运行 Codexcodex 提供商（默认全部）固定版本的 Codex、一个 codex，或 npx
antigravity通过 antigravity-acp 运行 Antigravity自行登录的账号已登录的 agy、Bun 和 npx
opencode通过 opencode acp 运行 OpenCode自行登录的账号已登录的 opencode
任意名称，acp通过其 command 运行任意 ACP 智能体自行登录的账号已安装并登录的对应智能体

修改之前#

遵循账号与模型中的说明：修改的文件是用户级 happy.toml；读取时应遮盖凭据，先备份，且绝不打印或复制凭据。

添加执行框架#

账号保持不变。为每个执行框架添加一张 [harnesses.<id>] 配置表；写入该表即启用，设置 enabled = false 则再次禁用。内置 ID 无需指定 type。

[providers.claude]                       # built-in; shows as "Current CLI"
enabled = true

[providers.claude_alex_acme]
type = "claude"
name = "alex acme"
oauth_token = "<from claude setup-token>"

[providers.codex]                        # built-in; shows as "Current CLI"
enabled = true

[harnesses.claude_code]                  # Claude Code on these accounts
providers = ["claude", "claude_alex_acme"]   # default: every type = "claude" provider

[harnesses.codex_cli]                    # Codex CLI on every codex account
# command = "codex"                      # optional: a codex of your choice
# args = ["app-server"]

[harnesses.antigravity]                  # shows as "Antigravity"

[harnesses.opencode]                     # shows as "OpenCode"

[harnesses.goose]                        # any ACP agent
type = "acp"
name = "Goose"
command = "goose"
args = ["acp"]
env = { GOOSE_PROVIDER = "openai" }

[harnesses.happy] 默认存在。为它设置 providers = [...]，可将 Happy 自身的循环限制在这些账号上；或者设置 enabled = false，只保留外部智能体。

Claude Code 使用账号的 oauth_token、api_key、auth_token 或 config_dir；对于内置 claude，则使用机器上的 Claude Code 登录状态。Codex CLI 使用账号的 api_key，或者将存放 auth_file（文件名必须为 auth.json）的文件夹作为 CODEX_HOME；内置 codex 则使用 ~/.codex。Antigravity 和 OpenCode 使用自己的登录状态；若要改用密钥，请在它们的执行框架上设置 api_key。通用 acp 智能体只能通过 env 或自身登录获得凭据。

然后重新加载守护进程。

模型#

每个智能体自行决定提供哪些模型。每次守护进程启动时，它会在后台针对每个账号启动一次所有已启用的执行框架，打开一个空会话但不发送提示词，读取智能体提供的模型与推理力度，并保存结果。模型 ID 为 <harness type>/<the agent's own model value>，例如 claude-code/opus、codex-cli/gpt-6.1-sol、opencode/openai/gpt-5.5；通用智能体则形如 acp/goose/<model>。

选择器会列出每个账号上各执行框架的模型：Happy 的模型旁边会出现 Claude Code · Opus 等模型。在智能体首次返回结果之前，Claude Code、Codex CLI 和 Antigravity 会提供一个简短的内置列表；OpenCode 和通用 ACP 智能体则不提供任何模型。如果某个智能体始终没有返回结果，守护进程日志会说明原因，通常是未登录或命令不存在。

执行框架可以从智能体提供的模型中进行筛选、隐藏和排序：

[harnesses.claude_code]
include_models = ["claude-code/opus", "claude-code/sonnet"]   # only these, in this order
exclude_models = ["claude-code/haiku"]

智能体未提供的 ID 会被忽略，且 exclude_models 优先。账号自身的 include_models 和 exclude_models 仍作用于其上的所有模型，因此，如果账号已经设置筛选，也应在其中列出 Claude Code 模型。智能池绝不会轮换外部智能体：Claude Code 或 Codex 对话始终留在启动它的账号上。在 Happy 循环和外部智能体之间切换对话，会通过交接开启一个全新的上下文。

子智能体#

任意 Happy 智能体都可以通过 create_agent 创建子智能体，通过 create_subtask 创建子任务，并使用其自身执行框架可访问的任何执行框架。两者都接受 harness、provider、model 和 effort；省略 harness 或 provider 时，如果创建者自己的对应选项能提供该模型，就沿用它；否则使用唯一能提供该模型的选项。工具描述会列出智能体可以用来启动其他智能体的模型，每个模型一行，包含其执行框架、账号和推理力度；内容固定为对话开始时的状态，之后不变，以保持提示词缓存有效。当列表变化时，智能体会收到一条隐藏的系统通知，列明删除和新增的行。agent_options 列出当前模型，而 agent_options({ usage: true }) 还会补充各账号的额度：Claude、Codex 和 Grok 账号使用守护进程最新读取的额度，Antigravity 使用它自行报告的额度。

默认情况下，Happy 自己的循环只能访问那些运行 Happy 自身无法运行的模型的外部执行框架，目前是 antigravity；Claude Code、Codex CLI 和 OpenCode 运行的模型，Happy 已经可以运行。外部执行框架可以访问其他所有外部执行框架，但不能访问 Happy 自己的循环。每个执行框架始终可以访问自身。subagent_harnesses 可替换某个执行框架的默认规则：

[harnesses.happy]
subagent_harnesses = ["antigravity", "claude_code"]   # Happy may also start Claude Code agents

[harnesses.antigravity]
subagent_harnesses = []                               # Antigravity agents start only Antigravity

外部执行框架上的子智能体是一个普通 Happy 智能体，拥有自己独立的外部会话。外部智能体自身创建的子智能体（Claude Code 的 Task 工具、Codex 的智能体）则留在其内部；Happy 会将其中每个显示为一次工具调用。

从 Happy 使用 Antigravity#

要让 Happy 智能体使用用户的 Google 账号启动 Antigravity 会话：

  1. 在机器上安装 Antigravity 的 agy、Bun 和 Node 的 npx。让用户运行一次 agy 并登录；Happy 绝不处理 Google 登录。
  2. 添加 [harnesses.antigravity] 并重新加载守护进程。Antigravity 账号会携带其模型出现在选择器中，例如 antigravity/gemini-3.8-flash。
  3. 在任意 Happy 会话中，请求创建 Antigravity 子智能体或子任务。智能体使用 create_agent 描述中列出的 Antigravity 模型（agent_options({ usage: true }) 会补充各额度窗口的剩余额度，来源为 agy -p /usage，最多每五分钟读取一次），并以 model = "antigravity/gemini-3.8-flash" 启动。

额度目前只对智能体显示；应用的用量面板尚未展示 Antigravity。

通用 ACP 智能体#

通用智能体只有接受通过 ACP 配置的 HTTP MCP 服务器，才能获得 Happy 的工具。它的模型选择器必须是类别为 model 的 ACP 会话配置选项。Happy 的权限模式会响应智能体的权限请求（Read only 会拒绝这些请求）；智能体不经询问自行执行的所有操作，都遵循它自己的设置，因此应将这些设置调整为符合用户预期的状态。

检查#

  1. 在临时项目中（参见测试已部署节点），使用新执行框架的模型启动一个会话，并确认其模型出现在选择器中。
  2. 让它使用自己的工具创建文件，再调用一个 Happy 工具，例如列出项目。确认两项操作都已执行。
  3. 在它执行长时间运行的命令时发送第二条消息，确认它会据此调整方向。
  4. 在 Happy 会话中，让它调用 agent_options，确认当 Happy 可访问新执行框架时，其模型已经列出；然后让它在该执行框架上创建一个子智能体。
