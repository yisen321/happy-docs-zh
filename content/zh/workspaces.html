项目与工作区#

项目是你指定给 Happy 的一个文件夹。工作区是智能体开展工作的文件夹。通常两者是同一个文件夹。当两项工作会同时修改同一个仓库时，各自就会获得独立工作区：从远程主干分出的独立分支上的 Git worktree。

要添加项目，只需告诉参谋长：

  • 示例

    将 github.com/acme/api 克隆为新项目并完成设置

添加项目#

导入操作只是登记文件夹。Happy 不会移动或复制它，也不会初始化 Git。目录树中任意位置的 AGENTS.md 都会被在那里工作的每个智能体读取，并在发生变化时重新读取。全局 AGENTS.md 适用于每个项目。

Happy 如何创建工作区#

  1. 获取 origin 的更新，并从远程主干分出分支。不会触碰项目文件夹中检出的内容、HEAD 或分支。
  2. 预留名称、~/Happy/Workspaces（macOS）或 ~/happy/workspaces（Linux）下的文件夹，以及 worktree/<name> 分支。
  3. 在后台执行 git worktree add。
  4. 复制 workspace.sync 中列出的文件（例如被 Git 忽略的 .env），并在项目根目录中的副本变化时持续同步。
  5. 运行 workspace.setup_commands，例如 pnpm install --frozen-lockfile。

检出和文件同步成功后，工作区就已就绪；设置命令失败会记录为警告。工作区的构建缓存从空开始。没有 Git 的项目会直接复制其文件夹，而不是创建 worktree。

新工作区以其第一个对话的名称命名，分支名也随之变化。你亲自命名的工作区，智能体绝不会重命名。

归档工作区#

操作立即生效且不可逆：工作区从列表中移除，worktree 和文件夹在后台删除，分支保留在 Git 中。工作完成或放弃后再归档。在 Auto 模式下，由智能体发起的归档会经过审查。

智能体如何在另一个工作区中工作#

智能体绝不会通过路径直接编辑另一个工作区。工作必须从工作区内部开展。

  • 子任务：会话列表中的完整对话，拥有独立的新工作区，由创建它的智能体担任协调者。只有机器人及其子任务能创建这类对话。

只有创建工作区的会话可以将其归档。

何时创建工作区#

当某项工作会与其他工作并行，且它们的改动可能冲突时。这是唯一的理由。不过，当前工作的子任务，无论有多少子智能体协助，都应留在当前工作区。

工作区显示哪些改动#

相对于当前分支与远程默认分支（origin/main）的共同祖先来计算改动，只有不存在远程时才回退到本地默认分支。Desktop 在对话旁显示已修改文件。

[workspace]
setup_commands = ["pnpm install --frozen-lockfile"]
sync = [".env"]
protected_sync = [".env.production"]
