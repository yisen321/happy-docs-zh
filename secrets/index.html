密钥管理#

Happy 只会把 API 密钥交给明确指定它的那一条命令。模型看到的是 ID 和变量名；实际值从你机器上的密钥目录注入该命令的环境中，不会流向其他地方。

要保存密钥，只需告诉参谋长：

  • 示例

    把 ~/keys/openai.env 中的 OpenAI API 密钥保存为名为 openai 的密钥

每个安装共用一份密钥目录#

密钥保存在运行 Happy Agent 的机器上的同一份目录中，由该安装的所有智能体共享。一个密钥以简短 ID 将一个或多个环境变量组成一组，并带有描述以及每次写入都会变化的版本。github 和 project-git 两个 ID 专门保留给 Happy 自行管理的密钥；API 会列出它们，但不会更新它们。

创建与更新密钥#

  • 让智能体操作。create_secret 可接受工具调用中内联提供的值，或主机上 .env 文件的绝对路径。两种方式在 Auto 模式下都会经过审查。内联值会留在对话记录中。使用 .env 路径则不会，因为守护进程会自行读取文件；这次读取是唯一使用主机文件系统访问权限的步骤。文件必须是普通文件，大小不超过 1 MiB，错误信息绝不会引用其中内容。
  • 在应用中操作。Settings → Happy Agent → Secrets → New secret（设置 → Happy Agent → 密钥 → 新建密钥）：填写描述、变量名和密码输入框中的值，并通过开关指定是否允许向智能体授予该密钥。命令面板中可在 Secrets 下找到此功能。
  • 通过 API 操作。使用 POST /v0/secrets，或使用 PATCH /v0/secrets/:id 并在 If-Match 中提供当前版本。客户端请求不经过 Auto 审查；审查针对的是智能体的操作。

update_secret 会替换整组内容，因此未包含的变量会消失；通过 API 操作时，null 表示删除一个变量。创建或更新都不会自动附加密钥。

模型能看到什么、绝不会看到什么#

list_secrets 和 reference_secret 返回 ID、描述、排序后的变量名、可用性和版本。任何工具结果、事件或 API 响应都不携带实际值：客户端的密钥记录结构会直接拒绝值字段，而解析实际值的方法并不是工具。Happy Desktop 也只列出相同的元数据，没有更多内容。

将密钥附加给智能体、工作区或项目#

授权让智能体能够使用密钥：可直接授予智能体，也可授予其工作区或项目；项目授权覆盖根目录及其下的全部工作区。授权不可修改；如需更改，先解除附加，再重新附加。attach_secret 和 detach_secret 仅作用于发起调用的智能体，绝不作用于它的子智能体，并且始终在 Auto 模式下经过审查。客户端通过 PUT /v0/secrets/:id/attachments/project/:projectId，或对应的 workspace、agent 接口进行授权。密钥可标记为不向智能体提供，此时新的授权会被拒绝；只要还有任何现存授权，就不能设为此状态。

命令如何接收密钥#

Claude、Codex 和 Grok 使用同一种方式：每个 shell 工具都接受 secrets 参数，Claude 对应 Bash，Codex 对应 exec_command，Grok 对应 run_terminal_command。该参数列出这一条命令所需的 ID，也可以不选。Happy 根据智能体自身、工作区及项目的授权解析这些 ID，并为命令启动一个新的主机 shell。启动前，它会从继承的环境中移除属于任何已附加密钥组的全部变量名，且不区分大小写，然后只加入选中的值；之后清除自身持有的副本。向携带密钥的后台命令输入内容也会经过审查。在运行器或 Docker 容器中执行的命令暂时不能选择密钥：值留在守护进程所在的机器上，所以只有那台机器上的命令才能接收。

密钥、沙箱与 Auto 审查#

选择密钥绝不会改变沙箱。在 Auto 模式下，只要命令指定了任何密钥组，就会经过审查；审查能看到选择了哪些组，但看不到实际值，命令仍在工作区写入模式下运行。离开沙箱是同一次调用中的独立请求，因此智能体可以申请密钥、申请完全访问，或同时申请两者。沙箱无法访问钥匙串和其他系统凭据存储；secrets 参数是实际值到达命令的唯一方式。完整权限模型见权限与沙箱。

密钥在磁盘上的存储位置#

密钥目录是 Happy Agent 在 ~/.happy/agent 下的 SQLite 数据库中的一张表，以明文 JSON 存储。文件权限为 0600，目录权限为 0700：这是访问控制，不是加密，因此被替换的值仍可能残留在 SQLite 页面和预写日志中。以内联方式提供给 create_secret 的值还会留在该会话的对话记录中；应用对话框和 .env 路径方式则不会在那里留下值。

Happy Desktop 中的密钥#

Settings → Happy Agent → Secrets（设置 → Happy Agent → 密钥）列出每个已保存密钥：描述、更新时间、Managed（受管理）、All agents（所有智能体）和 Scoped（限定范围）标记，以及变量名。New secret 打开上述对话框。附加、更新和解除附加通过智能体或 API 完成。

团队成员可以对密钥做什么#

团队服务器是一个 Happy Agent，共用一份密钥目录，没有任何密钥操作专属于所有者。任何已登录成员都可以通过 API：

  • 列出每个密钥的元数据；
  • 创建密钥，并替换或删除任何非 Happy 管理密钥的值；
  • 将任何允许智能体使用的密钥附加到任意智能体、工作区或项目，并解除任何授权。

这些请求携带成员的 WorkOS 令牌，并且与任何客户端请求一样，不经过 Auto 审查。在会话内，任何成员的智能体都可以为命令选择授予自身、工作区或项目的密钥，审查规则与个人机器相同。值留在执行命令的服务器上；不会发送到任何成员的应用或机器。只应在团队服务器上存放所有成员都有权使用的密钥。

Happy 与 Hermes Agent、OpenClaw 的比较#

以下是解决同一个问题的三种设计，信息均来自各项目自己的文档。

HappyHermes AgentOpenClaw
值存在哪里智能体机器上的 SQLite：明文 JSON，文件 0600，目录 0700~/.hermes/.env，以及启动时同步的 Bitwarden、1Password 或命令辅助程序SecretRef 指向的位置：env、file、exec，或状态 SQLite 中的存储；未加密，权限为 0600 和 0700
值如何录入经审查的工具调用、Desktop 对话框或 APIhermes config set 或 .env；管理器在启动时加载控制界面、CLI 或 dotenv 导入；secrets 工具通过掩码输入提示向用户索取
命令会收到什么仅收到它指定的密钥组，注入守护进程机器上的新 shell 中经过净化的环境；仅放行 terminal.env_passthrough 中的名称secret 类型：默认不注入；env 类型：明文；使用出口代理时，哨兵占位值仅在发往允许的主机时被替换
作用范围智能体、工作区或项目；逐条命令选择智能体进程网关全局、团队范围；出口流量受允许主机限制

Nous Research 的 Hermes Agent 将 API 密钥保存在 ~/.hermes/.env，非密钥设置保存在 config.yaml；命令行参数优先于配置，配置优先于 .env，日志会自动脱敏。启动时，它可通过 bws 从 Bitwarden Secrets Manager、通过 op:// 引用从 1Password，或从输出 KEY=VALUE 行的 shell 命令中获取更多密钥；各来源按优先级阶梯处理，Bitwarden 还可选用 AES-GCM 加密缓存。终端命令、代码执行和 cron 脚本运行时，受管理凭据会从环境中移除；技能中的 required_environment_variables 或 terminal.env_passthrough 列表可允许指定名称通过（Hermes 文档）。

OpenClaw 将配置中的明文凭据逐个替换为来源是 env、file、exec 或 store 的 SecretRef；明文方式仍可使用。其存储支持两种类型：只写且没有显示值调用的 secret，以及智能体可读取的 env。模型提供商凭据以哨兵占位值形式留在 Gateway 进程中，直到出口代理将其替换；文档说明这不构成进程隔离边界（运行时模型）。secrets 工具让智能体按名称、理由和主机请求凭据；由用户提供，聊天渠道收到的是链接而非值，并且刻意不提供写入智能体所提供值的操作（工具）。CLI 拒绝将 --value 用于 secret 类型，并执行保留 30 天的软删除；通过审计、配置、应用的工作流迁移现有配置，同时提供用于 1Password、Bitwarden、Vault、pass 和 sops 的 exec 配方。
