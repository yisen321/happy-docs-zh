无需开放端口：Happy 如何连接你的服务器#

Happy Desktop 连接远程 Happy Agent 时使用的是 Tailcat。Tailcat 是 Tailscale 的开源数据平面，不包含其控制平面。服务器无需开放任何端口，也不需要公网 IP，任何人都无需 Tailscale 账号。从你的机器到服务器的流量由 WireGuard 加密，而服务器仍会对隧道内的每个请求检查凭据。

Tailcat 是什么#

“由 Tailscale 打造、不依赖 Tailscale 服务的 Tailscale。”Tailcat 提取了 Tailscale 中负责传输数据包的部分——WireGuard 隧道、NAT 穿透和 DERP 中继——而不包含协调服务器。一端运行 Tailcat 服务器并获得一个简短的 tc… 地址；另一端连接这个地址。双方在中继处会合，尝试穿透 NAT 建立直接 UDP 路径，失败时继续使用中继。它运行在用户空间，不需要 root 权限，也不修改路由表或 DNS。Tailscale 为其提供有速率限制的免费中继；默认的 DERP 映射列出了这些中继，你也可以运行自己的中继。

Happy Agent 提供的额外能力#

  • 统一构建，统一版本。每个 Happy Agent 发布版二进制文件都内嵌 Tailcat v0.7.0。从源码检出运行或使用 npm 包时，则调用 PATH 中的 tailcat。
  • 稳定的身份。首次启用 Tailcat 时，Happy Agent 会运行 tailcat genkey，并将私钥保存在 ~/.happy/agent/tailcat/default.private.json 中，该目录仅允许所属用户访问。重启以及禁用后重新启用都不会改变地址。请勿复制或分享这个文件。
  • 固定端口。tailcat serve 将一个回环端口（默认为 24779）转发到 Happy Agent API：独立模式下对应仅所有者可访问的 Unix 套接字，团队模式下对应 HTTP 监听器。Happy Agent 严格绑定指定端口，绝不改用其他端口，因此地址和端口可以一起保存。
  • 进程托管。Tailcat 在 API 完成绑定后启动；若进程退出，会使用同一身份重新启动。运行期间，~/.happy/agent/tailcat/address 和 port 保存当前实际值。
  • 仅管理员可操作，并经过审查。只有处于活动状态的管理员机器人（默认是参谋长）才能开启或关闭 Tailcat，或读取其状态。修改这项设置属于互联网暴露操作；在 Auto 模式下，Happy 会在工具运行前审查具体操作。

参谋长部署服务器时，会先征得你的同意才启用此功能。手动配置时，在机器级 happy.toml 中写入：

[feature.tailcat]
enabled = true
port = 24779

团队创建时会向 Happy Cloud 注册 tailcat://ADDRESS:PORT，每位成员的 Desktop 都通过它找到服务器。

每次连接的过程#

  1. 一次性客户端密钥。Desktop 内的 Happy Agent 使用服务器地址启动 tailcat --key=new socks：为此次传输进程创建全新的 WireGuard 密钥，并在 127.0.0.1 上启动 SOCKS5 监听器。
  2. 在中继处会合。两台机器都主动连接地址中指定的中继区域。双方都不接受入站连接。它们通过中继交换路径发现消息，在 NAT 允许时切换到直接 UDP 路径。若不允许，则继续由中继转发。
  3. 端到端 WireGuard 加密。握手使用地址中的服务器密钥、地址中的预共享密钥，以及一次性客户端密钥。握手后的所有内容都是两台机器之间的密文。中继只转发已经加密的数据包，无法解密；它能够看到 IP 地址、时间、数据大小，以及用于路由的公钥。
  4. 隧道内部使用 HTTP。Happy Agent 通过 SOCKS 监听器连接到 server.tailcat 的固定端口，在隧道内使用其普通 HTTP API。API 令牌在隧道内传输，绝不会交给 Tailcat 进程。

地址不等于门锁#

tc… 地址编码了服务器的公钥、中继区域，以及自 Tailcat v0.6.0 起加入的 WireGuard 预共享密钥。Happy 始终启用预共享密钥，因此地址不仅是定位信息，也是机密：中继可以看到经过的服务器公钥，但没有预共享密钥就无法打开隧道。请将地址视为私密信息。

只有地址仍然无法进入系统。Happy 不使用 Tailcat 的客户端允许列表，因此任何持有地址的人都只能到达 Happy Agent 的认证边界，无法继续深入。隧道内的每个请求（包括健康检查），在独立模式下都需要服务器的持有者令牌，在团队模式下都需要团队登录。隧道成功打开后返回 401，表示传输正常，但凭据无效。

旧版 Happy Agent 内置 Tailcat v0.4.0，所创建的身份没有预共享密钥。服务器会继续提供服务并给出警告，各版本客户端都能连接。对于这样的地址，任何获知服务器公钥和区域的人（包括中继运营者）都能到达认证边界。替换身份密钥会生成当前版本的地址；团队随后需要通过 update_happy_team 发布新端点。反过来也有限制：Tailcat v0.5.0 及更早版本无法连接当前版本的地址。

手机的连接方式不同#

手机不使用 Tailcat。服务器通过 Happy 自己的中继，以端到端加密方式将会话发布到你的 Happy 账号，因此即使服务器离线，你的手机也能读取会话。

为什么选择 Tailcat#

我们希望你用连着酒店 Wi-Fi 的笔记本就能访问服务器，无需端口转发、VPN、公网 IP，也无需再注册一个账号。Tailcat 恰好解决了这个问题：它基于 Tailscale 在生产环境使用的同一套 WireGuard、magicsock 和 DERP 代码构建，开源，并使用 Tailscale 运营的免费中继。感谢 Tailscale。

手动试用#

在另一台机器上准备好 Tailcat，并从服务器取得三个值后，一条命令即可通过隧道检查独立服务器的健康状态：

TAILCAT_ADDRESS="tc..."   # ~/.happy/agent/tailcat/address
TAILCAT_PORT="24779"      # ~/.happy/agent/tailcat/port
HAPPY_TOKEN="..."         # ~/.happy/agent/token

tailcat socks "$TAILCAT_ADDRESS" curl \
  -H "Authorization: Bearer $HAPPY_TOKEN" \
  "http://server.tailcat:$TAILCAT_PORT/v0/health"
