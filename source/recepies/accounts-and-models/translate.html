Accounts, models, effort, and service tier#

Use this recipe when the user wants to add or pool provider accounts, limit or change models, set the default effort or service tier, or move existing sessions to another provider. To run Claude Code, Codex CLI, Antigravity, OpenCode, or another ACP agent itself on these accounts, add a harness. Everything here is machine configuration in the user happy.toml. Configuration is the reference.

Before editing#

  1. The file is ~/Happy/Config/happy.toml (macOS) or ~/happy/config/happy.toml (Linux). It is outside the workspace, so writes need reviewed full access.

  2. Read it with credentials redacted:

    sed -E 's/^([[:space:]]*(oauth_token|api_key)[[:space:]]*=).*/\1 "<redacted>"/' ~/Happy/Config/happy.toml

  3. Back it up: cp -p happy.toml happy.toml.bak-<timestamp>.

  4. Never print, copy, or send credentials, and never copy them between accounts or machines.

Accounts#

Each extra account is a [providers.<id>] table with a type and optional friendly name. Built-in claude, codex, and grok default to Current CLI; other accounts without a name use a readable version of the ID. Configuration, defaults, and pools continue to use the IDs.

Use the person's explicitly requested label verbatim. When proposing a name, prefer a recognizable email-style label, such as alex@example.com, alex@acme, or alex.work@example.com. Keep the username and domain details that distinguish the accounts; avoid overly short aliases. Omit redundant vendor or plan prefixes and suffixes: provider groups already supply that context. This is guidance for choosing a name. The product displays explicit names verbatim; it never shortens emails or appends plan names automatically.

Add an OpenAI-compatible vendor (OpenRouter, Together, Fireworks, DeepSeek, vLLM, LM Studio) with one table, filling models with the vendor's exact model IDs:

[providers.openrouter]
type = "openai_compatible"
name = "OpenRouter"
enabled = true
base_url = "https://openrouter.ai/api/v1"
api_key_env = "OPENROUTER_API_KEY"
models = ["deepseek/deepseek-v4.1-flash-1017"]
reasoning_field = "reasoning"

[providers.openrouter.request]
reasoning = { enabled = true }
  • Keep the key out of the file: put it in the variable api_key_env names, and reload the daemon from a shell that has it. Never paste the key into happy.toml, a commit, or a message.
  • Only list chat models that support tool calling. Check the vendor's model page first. On OpenRouter, supported_parameters must include tools.
  • Context window, image input, and efforts come from the vendor's /models in the background. Override any of them under [providers.<id>.model_overrides."<model>"]. The reference lists every setting.
  • To verify, check that GET /v0/config lists the models under the new provider, then run one turn that uses a tool.

Pool same-type accounts behind a smart provider and hide the members:

[providers.claude]
hidden = true

[providers.claude_work]
type = "claude"
enabled = true
hidden = true
oauth_token = "<from claude setup-token>"

[providers.claude_pool]
type = "smart"
strategy = "round_robin"
providers = ["claude", "claude_work"]
enabled = true

New agent or subagentStarts on a random member.
Later turnsStay on that member.
Auth or quota-exhaustion errorMoves to the next member.
Failure after output startedNot replayed on another account.
Not supportedWeights, usage-aware or priority routing, time windows, UI or API for pools.
SettingEffect
hidden = trueLeft out of model pickers; still routed to by a pool.
enabled = falseOff entirely, including routing through pools.
Delete the tableRemoves the account.
  • Sessions already on a hidden provider keep working. Move them to the pool with Switching existing sessions if they should rotate, and update defaults.provider if it names a hidden account.
  • A hidden account that no pool lists goes unused.
  • Pools combine only same-type accounts, and Bedrock only within one region; other members are skipped silently.

Effort#

Set effort under [defaults], such as effort = "medium". Use a level the model allows; the allowed levels are listed per model in GET /v0/config.

Service tier#

WhereSetting
[defaults]service_tier = "default", "fast", or "ultrafast".
Terminal/fast toggles the fast tier for the session.
New subagents and workspacesservice_tier: "priority" on the creation tool.
  • A tier applies only when the selected account and model support it. GET /v0/config lists each model's supported tiers per provider.
  • Fast inference uses twice the plan usage.

Switching existing sessions#

  1. GET /v0/agents/:agentId/mode to read the last submitted mode.
  2. PUT /v0/agents/:agentId/draft with that mode, changing only providerId, and keep the draft text the user already has.
  3. The agent's next message runs on the new provider.

Keeping the same model on a same-type account or pool is a compatible switch and keeps the conversation. An incompatible switch starts a fresh model context with a handoff note.

Apply and verify#

  1. Parse the file with a TOML parser, such as Python 3.11's tomllib, and check that every pool member exists. If it fails, fix the file or restore the backup.
  2. Apply the change as described in Applying configuration changes.
  3. Check that GET /v0/config or the model picker shows the pool or new account and not the hidden members, that defaults resolve, and that switched sessions run a turn.
