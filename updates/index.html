更新之后，从中断处继续#

即使智能体正在执行一个回合，你也可以安装 Happy Agent 更新；更新后，这个回合会继续运行。Happy Agent 会让当前步骤完成并保存，然后以新版本重新启动，再从那里继续同一回合。整个过程中，Happy 窗口始终保持打开，不会重新加载。

视频中的智能体回复是按脚本生成的。而在两个已发布的 Happy Agent 版本之间进行的更新，以及重启过程，都是真实的。

为什么更新通常会结束会话#

编程智能体运行在长期存活的进程中，而更新会替换这个进程。在许多智能体工具里，这意味着正在执行的工作就此结束：会话停止，你必须手动恢复或重新开始任务。因此，你往往会等到没有任务运行时才更新。

Happy Agent 如何在重启时保留回合#

Happy Agent 是你机器上负责运行智能体的服务；Happy 窗口则是连接该服务的客户端。Happy Agent 在运行过程中，会将每个回合的消息、工具调用及其结果持续写入 ~/.happy/agent 下的 SQLite 数据库。

更新只替换 Happy Agent 进程，不替换其他内容。Happy Desktop 下载新版本，请求当前运行的 Happy Agent 收尾，停止旧进程，再启动新版本。新进程从数据库读回未完成的回合并继续执行，窗口则重新连接。

收尾边界#

收尾并不是让智能体在重启期间持续工作，而是让当前步骤运行到可以保存的边界：正在运行的工具调用完成并写入结果，进行中的推理也执行完毕。新工作等待执行。随后旧进程退出，下一步在新版本上运行。

录屏中，更新开始时正在运行 node check.mjs。Happy Agent 等待不到四秒，该命令便执行完毕；新版本启动并重新连接大约用了六秒。随后，同一个回合运行 node verify.mjs，最终只完成一次：15 秒内完成。

你在 Happy Desktop 中会看到什么#

侧栏中的卡片会显示每个阶段：正在完成工作、正在关闭、正在启动、正在重新连接，最后显示已更新及耗时。在等待工作完成期间，卡片会列出正在等待的智能体；点击立即重启可跳过等待。这会停止仍在执行的操作：Shell 命令或文件编辑会被记录为已中断，重启后不会再次运行。

屏幕上的其他内容不会改变。窗口不会重新加载，也不会显示断开连接页面。Happy Agent 停止期间，保存草稿等后台写入操作会暂存，待服务恢复后发送，页面布局也不会跳动。

有更新就安装吧。更新之后，你的智能体会继续工作。
