在远程服务器上运行 Claude Code 和 Codex#

在服务器、VPS 或 Mac mini 上安装 Happy Agent，它就会自行在那里运行 Claude Code 和 Codex 工作：用一个智能体执行框架运行 Claude、Codex、Grok、Gemini 等模型，使用你已经付费的订阅。笔记本休眠时它仍会继续工作，你可以通过 Happy Desktop 或 Happy 手机应用独自控制，也可以与团队一起使用。

要设置远程服务器，只需告诉参谋长：

  • 示例

    在我的服务器 ubuntu@203.0.113.10 上安装 Happy Agent，命名为 Build box。使用我的 Codex 和 Claude 账户，并为 acme/api 配置 GitHub。

执行框架，而非遥控器#

  • 遥控器转发的是由厂商自己的 CLI 在你电脑上运行的会话。Claude Code Remote Control 和原版 Happy CLI 都采用这种方式。会话只能持续到那个进程或那台电脑停止运行为止。
  • Happy Agent 本身就是执行框架。它自行运行智能体循环，拥有自己的工具、沙箱和审查机制，直接调用模型。将它放到服务器上，笔记本休眠时会话仍会继续；Desktop 和手机只是查看并操作这些会话的窗口。

它复用你已经付费的订阅：

  • Claude 通过 Anthropic 自己的 Claude Agent SDK 接入，可以使用你的 Claude 套餐。Anthropic 曾宣布将 SDK 使用量转为单独的额度计费，随后又暂停该变更。其帮助中心使用 Claude 套餐运行 Claude Agent SDK 写道：

    2026 年 6 月 15 日更新：我们已暂停此前宣布的 Claude Agent SDK 使用政策变更。目前一切保持不变：Claude Agent SDK、claude -p 和第三方应用的用量，仍从你的订阅限额中扣除。

    其 10 月 7 日更新补充：“你仍然可以在订阅限额内使用 Claude Agent SDK、claude -p 和第三方应用。”

  • Codex 使用 Codex CLI 中的 ChatGPT 登录。OpenAI 帮助中心表示“各类 ChatGPT 套餐均包含 Codex”，OpenAI 也邀请开源应用基于这些套餐构建：“你的开源应用可以请求获准使用用户的 ChatGPT 套餐”（使用 ChatGPT 登录）。

Happy 的起点#

Happy 最初是 Happy CLI，即 npm 上的 happy。它在终端中原样运行 Claude Code、Codex 和其他兼容 ACP 的智能体，并让你通过 Happy 应用控制它们。如果你希望完整保留原版 CLI，并在自己的机器上使用终端，这仍然是合适的方式；其旧版文档仍在这里，处于维护模式。Happy Agent 和 Happy Desktop 是当前的新一代实现，由 Happy 自行在你的电脑或服务器上运行执行框架。

各自的优势：

  • tmux + SSH 或 Mosh。兼容所有终端智能体和工具，无需再信任新的系统。Mosh 能应对休眠和网络切换，Termius 在 iOS 和 Android 上支持它。
  • Remote Control。如果已使用 Claude Code 和 Claude 应用，无需额外安装；由 Anthropic 提供支持，权限提示会以推送通知发送到手机。Team 和 Enterprise 提供管理员管控。参见Happy 与 Remote Control 对比。
  • exe.dev。持久虚拟机，预装智能体，提供可在手机上使用的网页智能体 Shelley，以及随团队成员关系调整的虚拟机共享。无需设置服务。也可以在它上面运行 Happy Agent，见下文。
  • T3 Code。支持更多智能体：七种内置智能体，再加 ACP Registry。它有完善的免费手机应用，支持推送通知和实时活动，可跨多台机器路由工作，从桌面应用通过 SSH 启动服务器，社区也大得多（GitHub 2.68 万星；T3 表示有超过 40 万开发者使用）。
  • Happy Agent。三大模型家族共用一套运行时、沙箱和审查机制，桌面端与手机端专为智能体会话打造，团队模式让每个人保留自己的身份。代价是比其他方式需要更多设置，并且服务器由你运行和升级。

与团队共享#

同一台服务器可以为团队服务。在团队模式下：

  • 每位成员在自己的 Happy Desktop 中，通过 WorkOS 或你自己的身份提供商，以自己的 Happy Social 账户登录，并配对自己的手机。
  • 所有人都在服务器共享的项目和会话中工作。每次发言者变化时，智能体都会获知当前是谁；草稿与每个人的任务顺序仍彼此独立。
  • 所有人遵循相同的沙箱和审查规则：除非会话切到完全访问，否则命令都在操作系统沙箱内运行；Auto 会预先审查每个将越过沙箱边界的操作。
  • 服务器不再接受其 API 令牌。只有为该团队签发的 Happy Social 登录身份才能进入。

开始前请了解：所有工作都消耗服务器的 Claude、Codex 和 Grok 账户，而不是各成员自己的账户，且任何成员都能选择完全访问。没有逐会话邀请功能，我们也尚未提供移除成员操作。

设置时，告诉参谋长：“在我的服务器上创建一个名为 Acme 的团队。”详情见多人协作与团队。

Desktop 如何连接服务器#

Desktop 通过 Tailcat 访问服务器，它是一条内置于每个发布版本的加密隧道。Tailcat 是不含控制平面的 Tailscale 开源数据平面：无需账户、开放端口或公网 IP。SSH 仅在安装时使用。

  • 地址就是服务器的密钥。tc… 地址编码了服务器的 WireGuard 公钥、中继区域及 WireGuard 预共享密钥。私钥保留在服务器的 ~/.happy/agent/tailcat/default.private.json 中，因此只有那台机器能在该地址响应。
  • 端到端 WireGuard。你的机器每次打开隧道时都会生成一次性密钥，并与服务器执行标准 WireGuard 握手。此后的一切都在两台机器之间加密，仅在服务器上解密，再由 Tailcat 交给 Happy Agent。
  • 中继传输密文。双方先在 Tailscale 免费运行的 DERP 中继会合，该服务有速率限制，且不承诺可用性。随后双方尝试通过 NAT 建立直接路径，失败时仍由中继传输流量。中继能看到 IP 地址、时间、数据大小以及用于路由的公钥，但无法读取或更改内容。
  • 地址是秘密，但不是门锁。没有只包含在地址中的预共享密钥，任何人都无法打开隧道，中继运营者也不例外；请对地址保密。任何持有地址的人都能打开隧道，因为 Happy 不使用 Tailcat 的客户端允许列表，但隧道内每个请求仍需服务器 API 令牌或团队登录身份。较旧 Happy Agent（内置 Tailcat v0.4.0）生成的地址没有预共享密钥，仍然可用；对于这种地址，只需服务器公钥和区域即可到达登录检查。详情见无需开放端口。

手机不使用 Tailcat，而是通过 Happy 自己的中继：服务器将会话以端到端加密方式发布到你的 Happy 账户，因此服务器离线时手机仍可阅读。新发布的会话最多携带最近 50 条消息，不包含工具输出或模型推理。

部署过程中参谋长会询问什么#

你需要一台可通过 SSH 登录的 Linux 机器（见主机选择）。参谋长会端到端完成部署，只在需要你决定的地方暂停：

  • SSH：使用哪个账户，以及主机密钥。
  • 提供商账户：允许服务器使用哪些账户。复制凭据会让那台机器获得你的账户及其限额，因此它会尽可能优先让你在服务器上重新登录。
  • 登录：Claude、Codex、Grok 或 gh 的浏览器/设备登录代码，以及所有 macOS 钥匙串提示。
  • 对外访问：在服务器上开启 Tailcat。
  • Ubuntu 24.04：为 Happy Agent 二进制文件设置 AppArmor 许可，以便沙箱启动。
  • Git 身份：它会建议使用你的姓名和邮箱；若服务器应使用不同身份，请告诉它。

它会复制你的个人资料姓名和邮箱，安装服务、注册连接，在临时项目中运行测试任务，重启服务并再次检查。对于现有安装，它会先检查并保留，而不是替换。交接时会列出已通过的事项，以及仍需你处理的内容。

以后可以说：“升级 Build box 上的 Happy Agent。”

部署配方#

参谋长遵循 Happy Agent 仓库中的公开配方。阅读这些内容，就能准确了解它会在服务器上做什么：

  • 部署独立远程智能体：个人服务器，包括服务账户、提供商登录、服务、与 Desktop 的连接，以及 Git。
  • 创建并部署 Happy 团队：同一台服务器以团队模式运行。
  • 升级 Happy Agent：排空、备份、替换与验证，并保留你的设置。
  • 设置或修复手机访问：配对手机。
  • 所有配方

主机选择#

任何使用 systemd、可通过 SSH 登录并使用 sudo 的 Linux 机器都可以，Tailcat 无需入站端口。我们没有逐一测试所有选择；请按照各家文档创建机器。

Hetzner#

运行 Ubuntu 24.04 或 Debian 的云服务器；Arm（CAX）机型也可使用。若启用 Hetzner 防火墙，允许入站 SSH，不添加任何出站规则；未配置出站规则时允许所有出站流量。参见创建服务器。

DigitalOcean#

运行 Ubuntu 24.04 LTS 的 Droplet。Cloud Firewall 仅需允许入站 SSH。参见创建 Droplet。

AWS EC2 和 Lightsail#

使用 Ubuntu 24.04 LTS；登录用户为 ubuntu。Graviton（Arm）实例也可使用。安全组仅需允许入站 SSH。若在 EC2 上使用 Bedrock，附加最小权限的实例角色，就无需复制密钥。参见 EC2、Lightsail。

Google Cloud#

运行 Ubuntu 24.04 LTS 或 Debian 的 Compute Engine 虚拟机。Arm 机型也可使用。Tailcat 无需防火墙规则。参见创建 Linux 虚拟机。

exe.dev#

通过 ssh exe.dev new 创建的持久虚拟机，可使用 sudo。Claude Code 和 Codex 已预装，但 Happy Agent 使用自己的服务账户运行，因此会与登录用户分开登录提供商。使用你自己的密钥进行 SSH 连接；exe.dev API 令牌不能用于 SSH，也不是 Happy 凭据。exe.dev 自带的智能体 Shelley 会继续运行；Happy Agent 是与它并行的独立服务。参见 exe.dev 文档。

家中的 Mac mini 或旧笔记本#

运行 Linux 的笔记本与普通服务器一样可用。保持接电并打开屏幕盖；合盖通常会让机器休眠。

Apple 芯片或 Intel Mac 也可以。Happy Agent 使用 macOS 自带的沙箱，并作为 launchd 服务运行；我们不附带该服务定义，因此由参谋长编写。请让 Mac 保持不休眠。

树莓派及其他 ARM 开发板#

必须使用 64 位操作系统：uname -m 必须输出 aarch64。不支持 32 位操作系统（armv7l）。

尚未提供的功能#

远程节点只能通过 Tailcat 连接。Desktop 尚无“添加远程节点”按钮；请通过参谋长或 happy.toml 注册。
