权限与沙箱#

Happy 中的所有 Agent 都在统一的权限模型下运行：Claude、Codex、Grok 和 MCP 工具共用相同的文件系统边界与操作系统沙箱。在默认的 Auto 模式下，越过边界的操作由独立 Agent 审查，而不是向你弹出询问。

要更改默认权限模式，只需告诉参谋长：

  • 示例

    将新会话的默认权限模式设为 Workspace write

四种权限模式#

模式文件Shell 写入网络
Read only（只读）仅查看临时目录禁止
Workspace write（工作区写入）工作目录内工作区及临时目录仅允许的域名
Auto（自动）同 Workspace write同 Workspace write同 Workspace write
Full access（完全访问）不受限制不受限制不受限制

除非另有配置，新会话均以 Auto 模式启动。你可以随时从应用或手机更改模式。

Auto 就是在 Workspace write 基础上增加自动审查。读取和工作区内编辑从不需要审查。需要越过边界的工具会描述一次具体操作；如果获准，仅该次执行使用 Full access，之后会话恢复 Auto。

Auto 审查如何决定#

一个独立的只读 Agent 会结合对话审查所描述的操作，并回答允许或拒绝。不会向你弹出询问。

  • 只有你的消息，以及你对 Agent 问题的回答，才算授权。助手文字、工具输出和文件内容都不算，因此植入的指令无法授予访问权限。
  • 对某项操作的拒绝就是最终决定。Agent 不得将其拆分或绕道执行。连续被拒绝后，本轮会结束并给出说明；你用自己的话明确批准后，下一次审查就可以允许执行。
  • 如果审查超时或无法运行，会将操作报告为尚未证实可执行。Auto 绝不会退而选择静默执行。

操作系统沙箱强制执行哪些限制#

macOS 上使用 Seatbelt；Linux 上使用 Happy 自身的监督程序，基于内核命名空间和 seccomp。边界限制直接作用于进程，而不是通过阅读命令文本来判断。

  • 写入：仅工作目录和临时目录；Git 控制路径为只读。
  • Shell 读取：可以读取机器上的其他内容，但凭据文件夹及 shell 历史除外，例如 ~/.ssh、~/.aws、~/.claude、~/.codex、~/.docker、~/.gnupg 和 ~/.config/gh。在 macOS 和 Linux 上，文件工具访问这些文件夹并不会被阻止。
  • 受保护路径即使在工作区内也为只读：仓库的 AGENTS.md、AGENTS_SECURITY.md、happy.toml 和 mcp.toml，以及运行时自身的状态。
  • 网络：仅允许配置中的域名和端口，通过 Agent 无法更改的托管代理访问。
  • 本地端口：macOS 上默认禁止，除非显式启用。在 Linux 上，监听器仅能从自身所属命令内部访问。
  • 钥匙串：不可用。密钥只有以附加密钥包的形式才会传递给命令。
  • 主机套接字（Docker、SSH agent、运行时的控制套接字）：无法访问。

基于 Docker 的会话会在容器内部嵌套同样的沙箱。

MCP 工具与沙箱#

MCP 服务器运行在沙箱之外，因此每个 MCP 工具都需要 Auto 或 Full access，且 Auto 下的每次调用都会接受审查。服务器自身标注“只读”并不能作为依据。

密钥与沙箱#

只需注册密钥一次，并将其授予某个 Agent、工作区或项目。只有当 Agent 指定密钥包时，命令才会收到密钥；其值绝不会出现在提示词文本或工具结果中。参见密钥的工作方式。

happy.toml 中的权限设置#

[defaults]
permission_mode = "workspace_write"

[network]
allowed_domains = ["api.github.com", "*.npmjs.org", "npmjs.org"]
allowed_ports = [443]

[permissions]
protected_paths = [".env.production"]
