将机器人接入任意聊天服务#

当用户希望通过 Happy Agent 尚未内置支持的聊天服务与机器人对话时，请使用本指南，例如 Slack、Discord、Matrix 或公司内部聊天工具。一个称为“桥接程序”的小程序通过一条 WebSocket 在该服务与 Happy Agent 之间传递消息。Happy 保存对话、允许名单和待回复内容；桥接程序负责服务侧的所有事务。Telegram 是内置集成，另有专门指南。桥接协议是桥接程序的规范，配置文档则提供参考说明。

使用独立机器人，而不是参谋长#

对外接入的应该是为这项工作单独创建的机器人，绝不能是参谋长，也就是你。每个通过桥接程序与机器人对话的人，都会获得一个在该机器人文件夹内工作、能访问其可达资源的对话。因此，他们接触到的机器人，只应拥有用户为他们选定的文件夹和用途。

你只通过两种方式参与：一是对外开放机器人、修改开放设置或停止开放，所有修改工具都要求提供机器人的 botId；二是决定允许谁访问，因为每个对外开放机器人的访问申请都会进入你的对话。你拥有这些工具，是因为你是管理员机器人；对外开放的机器人永远不会获得它们。所有更改立即生效，无需重新加载。

工具用途
set_bridge_exported_bot对外开放机器人并写入令牌，或修改允许名单、令牌、陌生人处理方式或暂停状态。
get_exported_bot_status查看桥接程序是否已连接、允许哪些人，以及哪些人在等待批准。
approve_exported_bot_user用户同意后，允许提出申请的人访问。
deny_exported_bot_user用户拒绝后，拒绝提出申请的人。
remove_exported_bot停止对外开放（kind: "bridge"），删除令牌并丢弃尚未发送的回复。

用户做什么，你做什么#

步骤执行者
选择或创建 Happy 机器人你，使用用户提供的名称
对外开放机器人并写入令牌文件你
编写或选择桥接程序，并运行它用户，或由你在用户同意的项目中执行
为桥接程序提供服务自身的访问权限用户
在服务上向机器人发送消息用户
批准用户的访问申请用户确认后，由你执行
确认收到回复双方

1. 选择机器人#

先调用 get_exported_bot_status。如果机器人已经通过桥接程序对外开放，那么当前任务属于修改设置：跳到适用步骤。一个机器人最多只能有一个桥接接入；第二个服务需要第二个机器人。

如果用户指定了除你以外的现有机器人，使用 list_bots 查找其 ID。否则使用 create_bot 创建一个，并按其职责命名；如果用户没有偏好，就请用户提供名称。无论哪种情况，都要给它命名：人们只会通过桥接程序访问它，因此它永远收不到通常用于为其命名的第一条消息。

2. 对外开放机器人#

调用 set_bridge_exported_bot，提供：

  • botId：第 1 步中的机器人。
  • service：人们熟知的聊天服务名称，例如 Slack。该名称用于命名对话，例如“Ada Lovelace on Slack”。
  • tokenFile：桥接程序读取令牌的位置，可以是绝对路径，也可以相对于你的工作目录，例如桥接程序项目内部的路径。在工作区之外写入需要审核。
  • allowedUsers：仅在用户已经提供服务侧用户 ID 时设置，必须与桥接程序发送的 ID 完全一致。不设置 unknownSenders，使其保持为 "ask"。

结果会说明该接入正在等待桥接程序连接，列出令牌文件并提供连接 URL。令牌只写入该文件，仅文件所有者可读，不会在其他任何位置显示：Happy 只保存其摘要。绝不要打印、复制或粘贴令牌；如果文件位于 Git 仓库中，要在任何提交发生之前确保它已被忽略。

3. 运行桥接程序#

exported-bot-bridge.mjs 随本指南一起提供，通常位于 ~/.happy/docs/recipe/。这是一个以终端充当模拟服务的完整桥接程序：输入的每一行都作为某个人的消息，/attach <path> [text] 发送文件，/as <user ID> [name] 切换输入者，回复会连同接收人一并打印。它是最快验证接入效果的方式，也是真实桥接程序的起点。将它复制到独立文件夹，在其中安装 ws 软件包，然后带上令牌文件和连接 URL 运行：

pnpm add ws
node exported-bot-bridge.mjs /path/to/bridge.token 'ws+unix:///path/to/daemon.sock:/v0/exported-bots/connect' terminal "Ada Lovelace"

第三和第四个参数是发送的用户 ID 和名称。真实桥接程序保持相同结构，只需将终端替换为服务的 API：

  1. 使用请求头 Authorization: Bearer <token>，向连接 URL 建立 WebSocket。独立守护进程监听其 Unix 套接字，Node 的 ws 软件包通过 ws+unix:// URL 访问；团队守护进程则监听 TCP。
  2. 收到 hello 帧后，将每条一对一消息作为 message 帧发送，其中包含永久唯一的 id、发送者的 userId、回复所用的 chatId、发送者的 name，以及 text 或 attachments。连接断开时尚未得到回复的消息，要使用相同 id 重新发送。
  3. 将每个 reply 帧的文本和文件发布到服务，再回复包含其 seq 的 ack。已经交付的 seq 应跳过。将 typing 帧显示为服务的“正在输入”指示。
  4. 连接关闭后，采用退避策略重新连接。遇到 401 时停止，表示令牌已轮换或接入已移除；关闭码为 4000 时也应停止，表示另一个桥接程序接管了连接。

文件绝不会通过 WebSocket 传输；双方交换的是绝对路径。应在守护进程所在机器上运行桥接程序，使用能读取 Happy 文件、且其保存的文件也能被 Happy 读取的用户。Happy 会展示人们发给机器人的图片，并回传机器人生成的图片以及通过 present_files 展示的文件。运行在另一台机器上的桥接程序仍然可以交换文本。

4. 允许用户访问#

  1. 请用户在服务上向机器人发送消息。在用户尚未获准访问时，桥接程序会收到一条发给用户的固定通知，而消息内容尚不会传给机器人：

    感谢你的消息。这个机器人只与其所有者批准的人交流，因此你的申请已发送给所有者。如果申请获批，机器人会回复你刚刚发送的消息。

  2. 你的对话中会收到访问申请。其中列出机器人以及桥接程序发送的发送者用户 ID、用户名和显示名称，绝不包含其消息正文。请用户确认申请者就是自己。

  3. 调用 approve_exported_bot_user，传入 kind: "bridge"、机器人的 botId，以及申请中的 userId。对方会成为访客，暂存的消息会进入其新建的子任务，机器人随后回复。

其他人向机器人发消息时，也按相同方式询问。告诉用户谁在申请、申请访问哪个机器人；除非用户已给出指示，否则应询问是否允许。绝不能根据你对申请者的个人判断自行批准。Telegram 指南中的访问申请介绍了其余流程，适用于所有对外开放的机器人。

5. 验证#

检查以下事项：

  1. get_exported_bot_status 显示接入已连接，并列出用户的对话。
  2. 名为“<姓名> on <服务>”的子任务出现在该机器人下，而不是你下面。
  3. 用户在服务上收到了回复。
看到的情况处理方式
状态：正在等待桥接程序连接桥接程序未运行，或无法连接守护进程。查看其输出。
桥接程序收到 401 拒绝文件错误，或令牌已轮换或移除。通过 rotateToken 和 tokenFile 轮换令牌。
桥接程序收到 503 拒绝接入已关闭，或机器人已归档。启用接入或恢复机器人。
桥接程序以 4000 关闭两个桥接程序正在使用同一令牌。只运行一个。
消息因附件而被拒绝桥接程序必须将文件保存在本机，并发送普通文件的绝对路径。
状态：忽略了来自……的消息陌生人被忽略。设置 unknownSenders: "ask"，或直接允许其 ID。
申请中的 ID 与名单不同ID 按桥接程序发送的原值精确比较。允许申请中出现的 ID。

后续修改#

每次修改都需要指定对外开放机器人的 botId。get_exported_bot_status 也接受它，用于显示单个机器人的状态。

修改内容方式
允许某人访问使用 approve_exported_bot_user，或调用 set_bridge_exported_bot 并提供完整的新 allowedUsers。
将某人移出名单调用 set_bridge_exported_bot 并提供完整的新 allowedUsers。其子任务和访客身份仍保留。
永久拒绝某人使用 deny_exported_bot_user。对方也会被移出名单。
停止或恢复访问申请调用 set_bridge_exported_bot，设置 unknownSenders: "ignore" 或 "ask"。
重新开始某人的聊天归档其子任务。下一条消息会创建新的子任务。
暂停对外接入调用 set_bridge_exported_bot 并设置 enabled: false。桥接程序会断开连接；回复仍保留。
更换泄露的令牌调用 set_bridge_exported_bot，提供 rotateToken: true 和 tokenFile。旧令牌立即失效。
停止对外开放调用 remove_exported_bot 并提供 kind: "bridge"。令牌停止工作，尚未发送的回复会被丢弃。

用户应当了解的事项#

  • 所有获准访问的人都是访客：Happy 知道他们的名字，但他们绝不能登录 Happy 或打开应用。访客消息属于他们自己的请求，绝不视为用户指令，包括 Auto 权限判断是否允许操作时；他们的会话始终以 Auto 模式运行。机器人仍会利用自己能访问的所有资源为他们工作，因此只应允许用户信任其使用机器人文件夹和工具的人。
  • 任何持有令牌的人都能以任意获准访客的身份发送消息。保持令牌文件私密，如果令牌可能泄露，应立即轮换。
  • 桥接程序会收到机器人展示的所有回复和文件。只运行用户信任的桥接程序。
  • 陌生人获批之前，其输入的任何内容都不会传给任何机器人；你只能看到他们是谁。
  • 每个人只能看到自己的对话。其子任务在机器人的文件夹中工作，这也是对外接入需要独立机器人的原因。桥接程序的用户 ID 只属于该桥接程序，因此同一个人在两个桥接程序中会被视为两个访客。
  • 回复在 Happy 中等待，直到桥接程序确认交付；因此离线过的桥接程序会在重新连接后补齐消息。机器人写出的所有内容都会发送，包括工作期间的简短进度说明；它展示的文件会随针对每条消息的最后一条回复一起送达。
